## 결론과 검증 수준

확정 입력·실제 대상·기준 원문을 파일로 저장하고 다음 실행에서 다시 읽었다. 기존 Fragment 저장 함수를 사용한 재실행은 추가 API 쓰기 없이 복구되었고, 다른 내용이나 동시 수정은 충돌로 거절되었다. 글·카테고리·프로젝트의 파일 예시에서는 규약에 따라 기존 내용과 비교한 뒤 재저장·중복 추가를 하지 않아 파일 차이가 없었다.

**Fragment는 현재 앱 함수의 동작을 검사했다. 나머지 대상은 규약을 따르는 참조 절차와 인계 자료를 검사했다.** 모든 AI가 그 절차를 자동으로 따르거나 현재 앱에 글·카테고리·프로젝트 처리 엔진이 생겼다는 뜻이 아니다. 웹 미지원 작업의 자동 라우팅도 구현하지 않았다.

## 실행과 운영 보호

`npm test`가 새 시나리오 13개를 기존 검사와 함께 실행한다. 관련 검사만 실행하려면 `npx vitest run tests/integration/ai-handoff.test.ts --reporter=dot`를 사용한다. 기존 공통 CI의 `npm test`에 포함되므로 별도 워크플로를 만들지 않는다.

각 사례는 `.fragment-test/handoff-<임의 접미사>/` 안에 합성 콘텐츠·확정 요청·인계 파일을 만든다. 요청은 YAML로 저장하고 인계 기록의 참조를 통해 다시 읽는다. 수정 재실행은 저장한 기준 SHA와 원문으로 기존 상태를 복원한다. 운영 콘텐츠를 복사하거나 수정하지 않는다.

Fragment의 HTTP 호출은 테스트에 주입한 파일 기반 모의 API에서만 처리한다. 예상한 테스트 저장소·브랜치·카드 경로·조회/저장 외의 요청은 거절하며 실제 네트워크로 전달하지 않는다. API 커밋 SHA는 합성 값이다. 테스트용 토큰은 인증되지 않는 고정 문자열이며 실제 계정·OAuth·GitHub 커밋·push·발행은 발생하지 않는다. 모의 API 호출은 실제 사용자 승인 절차를 테스트한 증거가 아니다.

파일 차이는 경로별 SHA-256 지문을 대조한다. 글·이미지·설정뿐 아니라 중단된 예시 작업 로그와 STATUS도 포함한다. 재실행 때 원문을 읽고 비교한 뒤 저장하지 않는 절차는 로컬 쓰기 횟수도 증가하지 않는지 확인했다. 진단용 사본은 ignored 폴더에 보존한다.

## 인계 때 확인할 것

1. 같은 요청 식별자와 확정 입력을 보존한다. 입력을 파일 참조로 전달하면 원문도 보존하고, 읽을 수 있으면 원문 SHA-256 지문을 함께 남긴다. 지문은 줄바꿈·들여쓰기 변경도 감지한다.
2. 실제 경로·ID·브랜치와 기준 SHA·원문을 넘긴다. 이전 보고를 그대로 믿는 대신 최신 원본과 대조한다. 이름이 같은 후보는 정확한 대상을 확인한다.
3. 이전 응답이 유실되면 상태를 미확인으로 유지하고 조회부터 한다. 기존 결과와 같으면 새 저장을 하지 않는다. 조회에 실패하면 새 생성으로 우회하지 않는다.
4. 승인·초안 저장·커밋·push·발행·배포 증거를 구분한다. 입력 지문이나 요청서의 승인 문자열은 사용자 통과 판정을 대신하지 않는다.
5. 웹에서 지원하지 않는 글·카테고리·프로젝트는 확정 자료를 저장소 작업으로 넘긴다. Fragment 폼에 대신 등록하거나 저장 완료라고 보고하지 않는다.

## 한계와 다음 작업

특정 AI를 실제로 다른 채팅 세션에서 실행해 평가한 결과는 아니다. 사람이 작성한 확정 입력을 복구하는 절차와 현행 함수의 검증 결과다. 프로젝트의 영구 ID·일반 작성 엔진·전체 관계 정책 강제·의미 비교 자동화는 후속 범위다.

기존 Fragment 재시도 검사는 이미 알고 있는 고정 ID로 실행했다. 현재 웹 폼이 발급한 UUID를 응답 유실 후 새 세션에서 모르는 경우의 자동 중복 방지를 증명하지 않는다. 그 경우 규약대로 최신 초안의 후보·내용을 먼저 조회하고 확인할 수 없으면 미확인으로 인계해야 한다.
