# Node.js 보안 업데이트 계획 — NSEC01

작성일: 2026-10-24

## 목적과 실행 근거

- Node2Shell(CVE-2026-111497)을 포함한 2026-10 보안 수정 적용 및 기존 블로그 동작 보존 목적임.
- 사용자의 “업데이트 전 영향도 파악 → 문제 대응 확인 → 계획 수립 후 작업 진행” 요청에 따라 조사·격리 검증·업데이트를 진행함. 커밋·push·main 반영은 기존 저장소의 사용자 통과 절차를 별도로 따름.
- 작업 브랜치: `chore/node-security-20261024`, 폴더: `.worktrees/node-security/`, 기준: 최신 `origin/main`의 `bcec1df69345dfd7e5e757d66cfe4454f709b240`임. AI 기능 개발 브랜치의 미승인 AIR01 보고서와 원래 폴더의 삭제 3건은 보존함.

## 업데이트 전 영향도와 대응

| 대상 | 확인된 영향 | 대응 및 검증 |
| --- | --- | --- |
| PC Node.js | Windows x64 MSI 설치 24.14.0이며 24.22.1 보안 수정 전 버전임 | 공식 24.22.1 ZIP을 SHA-256 대조 후 격리 실행하고, 검증 후 같은 버전 MSI로 업데이트함 |
| CI | 마지막 운영 배포에서 Node.js 20.20.2 사용함. Wrangler·Miniflare 등은 이미 Node >=22, sanitize-html은 >=22.12 요구함 | 두 작업의 런타임 기준을 `.node-version` 24.22.1로 통일하고 기존 검사·빌드·preview·OAuth 모의 연동 보존함 |
| 버전 선택 | PC는 24 계열이므로 같은 계열 보안 버전으로의 변경임. CI는 20→24로 주 버전 변경임 | 26으로의 추가 주 버전 변경을 피하고, 의존성 lock을 유지해 변경 원인을 런타임에 한정함 |
| 네이티브 모듈 | esbuild·sharp·workerd가 포함됨. lock의 sharp-win32-ia32 예외는 현재 x64에 설치되지 않는 선택 의존성임 | 새 런타임에서 깨끗한 npm ci·이미지 포함 빌드·Worker 로컬 실행 검사함. 실패 시 해당 경로를 먼저 분류하고 무관한 패키지 전체 갱신을 하지 않음 |
| TLS·DNS·fetch | 보안 릴리스는 Brotli 외에 OpenSSL·Undici·인증서·DNS 동작도 변경함 | 로컬 HTTP·mock OAuth·초안/발행 흐름 검증함. 운영 OAuth 실제 계정 경로는 사용자 승인 후 운영 반영 시 별도 확인하며 로컬 성공으로 대체하지 않음 |
| npm | PC에서 현재 선택되는 npm은 11.12.1, 새 ZIP에는 11.19.1 포함됨 | 새 npm으로 기존 lock 설치 가능 여부를 확인하고 의존성 버전 변경 없이 유지함 |
| 전역 CLI | 설치된 6개 전역 도구의 Node 엔진 조건은 24.22.1과 호환됨 | 패키지 재설치·업데이트 없이 새 Node에서 비파괴 버전 조회로 시작 가능 여부 확인함. 실제 계정·업무 전체 흐름 검증과 구분함 |
| 실행 중인 프로세스 | 현재 Program Files의 Node.exe 프로세스 다수 실행 중임 | 프로세스를 강제 종료하지 않음. MSI가 앱을 강제 종료하지 않도록 설정함. 기존 실행은 업데이트 후에도 이전 코드를 사용할 수 있어 재시작 필요를 알림. 설치가 막히면 무리한 파일 교체 없이 상태·해결 절차를 기록함 |
| 공개 블로그·OAuth Worker | GitHub Pages 정적 산출물과 Cloudflare 관리 런타임임 | 게시물·UI·OAuth 인증/권한·Worker 배포 설정은 변경하지 않음. PC 업데이트가 Cloudflare 자체의 Brotli 패치 상태를 증명하지 않음을 명시함 |
| Actions 자체 실행기 | setup-node로 선택한 프로젝트 Node와 JavaScript Action을 구동하는 runner 내부 Node는 별개임 | GitHub-hosted runner 내부 런타임 패치는 공급자 관리 영역임. GitHub는 2026-09-23 이후 Action 실행을 Node24로 전환했다고 공지함. 프로젝트의 node-version:20 다운로드·실행은 여전히 별개로 가능하므로 이를 24.22.1로 바꿈. 내부 런타임의 정확한 패치까지 이 설정으로 보장하지 않음 |

## 선택한 구조

- `.node-version`에 `24.22.1`을 고정하고 GitHub Actions 두 Setup Node 단계에서 같은 파일을 읽음.
- `package.json`의 Node engines 범위는 `>=24.22.1 <25`로 두고 `.npmrc`의 `engine-strict=true`로 구형 런타임 설치를 거절함. 버전 파일은 재현 가능한 CI 기준, engines는 같은 24 계열의 보안 하한임.
- `package-lock.json`은 루트 engines 메타데이터만 맞추며 의존성 버전·integrity는 보존함.
- `CLAUDE.md`의 기존 Node >=18.20.8 안내를 새 기준·설치 후 재시작 안내로 갱신함.
- 버전 재발 방지 검사는 실제 workflow 버전 참조와 설치 엔진 정책을 검증함. 취약점 악용 코드를 실행하지 않음.

## 실패 시 조치

- Node20→24 호환성 실패는 새 격리 환경에서 재현하고 모듈/도구·npm·TLS·포트 충돌·기존 실패를 구분함. 기존 기대값 삭제·skip 또는 보안 수정 전 버전으로의 영구 회귀를 해결로 삼지 않음.
- Windows 파일 잠금·관리자 권한 문제면 기존 프로세스 강제 종료·Program Files 수동 덮어쓰기 없이 설치 결과를 기록함. 검증된 ZIP은 재개용으로 유지하며 이를 PC 전체 업데이트 완료라고 표시하지 않음.
- 저장소 변경은 별도 브랜치에서 취소 가능함. 적용 전 이미 실행 중인 프로세스의 메모리 내 코드는 새 설치로 교체되지 않음.
- CI 변경은 최종 통과 후 개발 브랜치에 push해 실제 Linux CI로 검증하고, main 반영은 사용자가 PR로 선택함. 개발 브랜치 로컬 성공만으로 운영 빌드 환경 업데이트 완료라고 표시하지 않음.

## 범위와 제약

- PHP 신규 설치·게시물 변경·OAuth 권한 변경·전역 CLI 버전 갱신·다른 PC 프로젝트의 마이그레이션은 포함하지 않음.
- 새 Node가 엔진 조건을 만족한다는 사실과 다른 모든 PC 프로젝트의 실제 동작 보장은 구분함.
- Brotli 1.2.0이라는 버전 문자열만으로 보안 패치 적용 여부를 판단하지 않음. Node 24.22.1은 같은 Brotli 버전 표기를 유지하면서 수정 커밋을 backport함.
- 완료 결과는 후속 로그에 실제 검사 수·실패·설치 상태와 함께 기록함.
- 실행 결과: PC Node24.22.1 설치 exit0·기존 npm11.12.1 유지·설치 후 clean install/109개 통과함. 계획의 앱 종료 방지 옵션은 새 MSI에만 적용됐고 구버전 제거에서 Restart Manager의 종료·재시작 기록이 발생함. 사전 안내를 충족하지 못한 예외·프로세스 상태 복구 미확인·다음 설치의 사전 작업 저장/종료 원칙을 [검증 보고](../guide/Node.js-보안-업데이트-검증.md)에 명시함. 이 작업의 커밋·원격 CI·main 반영은 아직 대기임.
- 검증 도중 같은 폴더에서 비교 빌드와 개발 서버 검사를 겹쳐 실행한 회차에서 초안 E2E 15개 실패함. 이후 이전 Node와 새 Node의 단독 실행은 각각 15개 통과함. 정확한 최초 실패 원인은 미확정이며, 후속 빌드·E2E는 같은 작업 폴더에서 순차 실행함. 기대값 변경이나 skip으로 우회하지 않음.
- H02 검사 보완: 기존 테스트가 Node 러너의 클릭 자동 대기·expect 재시도까지 Date.now()로 측정해 새 런타임에서 2,018~2,042ms로 실패함. 별도 브라우저 계측에서는 실제 클릭→준비 약 1,576ms로 확인함. 그래프 코드는 보존하고, 브라우저 클릭 이벤트부터 캔버스·상태가 준비된 프레임까지 performance.now()로 측정함. 기존 로컬 2초·CI 3초 기준 및 실제 노드 선택 동작 검증은 유지함. 이는 한도 완화가 아니라 측정 대상과 시계의 일치임.
