# AI 콘텐츠 작업공간 분리 최종 보고서

## 결론과 현재 상태

개발 STATUS·로그와 콘텐츠 작업 메모의 갱신 범위를 분리하고, 하나의 작성 작업 안에 개별 확정 요청을 보존하는 안내·템플릿을 연결했다. 실제 CLI를 격리 사본에서 실행해 작업 간 기록 보존, 복수 요청, 재실행, 오래된 메모와 실제 상태의 차이, 원문·자산 인계의 경계를 확인했다.

공통 규칙은 ACWR01 사용자 통과 커밋 `be3fba7`, 작업공간 예시·복사용 지시문은 ACWT01 사용자 통과 커밋 `454f973`으로 개발 브랜치에 저장했다. ACWV01은 신규 통합 검사 7개와 이 검증·마감 자료가 현재 검토 대상이다. 현재 자료의 통과·커밋·push와 main 병합·운영 공개는 각각 구분한다.

## 다음 AI가 사용할 문서와 작업 순서

평소 위임은 [AI에게 블로그 작업을 맡기는 방법](./guide/AI-콘텐츠-운영가이드.md), 실제 폴더·초안·HANDOFF는 [작업공간 사용 안내](../templates/ai-content/workspace/README.md), CLI는 [자동화 운영 가이드](./guide/AI-콘텐츠-자동화-운영가이드.md)를 사용한다. 저장소 규칙의 원문은 [AGENTS](../AGENTS.md)와 [콘텐츠 규약](./guide/AI-콘텐츠-작업규약.md)이다.

1. 실제 프로젝트 루트의 STATUS를 읽어 개발 현황·문서 위치를 확인하고 현재 사용자 요청을 분류한다. 무관한 개발 대기를 콘텐츠 승인 대기로 이어받지 않되 같은 파일·스테이징 충돌은 확인한다.
2. 기존 작업공간·HANDOFF와 실제 콘텐츠 후보를 찾아 재개한다. 새 작업일 때만 작업 폴더를 정한다. 일반 콘텐츠 진행으로 루트 STATUS·개발 로그를 갱신하지 않는다.
3. 초안·스킬 메모는 작업공간에서 갱신한다. 개별 변경이 확정되면 `requests/<request_id>/request.json`과 같은 요청 폴더의 plan.json을 보존한다. 후속 변경과 같은 입력의 재시도를 구분한다.
4. 실제 root·원문·자산·기준을 대조해 계획·적용·재실행을 수행한다. HANDOFF의 완료 문구는 적용 증거가 아니며 실제 파일·receipt·journal을 확인한다.
5. 관련 검사·해당 변경의 사용자 통과 뒤 기존 승인·커밋·개발 브랜치 push 절차를 따른다. 콘텐츠 작업공간이 Git 인덱스나 사용자 승인 범위를 자동 분리하지는 않는다.

작성 스킬에는 해당 작업의 초안·메모 위치를 전달한다. 경로 지정을 지원하지 않으면 충돌을 설명한다. 새로운 CLI task_id·작업 DB·잠금 엔진은 도입하지 않았다. 기존 완료 기록·잠금·저널·준비 파일 경로와 복구·승인 계약도 유지했다.

## 실제 검증 결과

신규 [작업공간 통합 검사](../tests/integration/content-workspace.test.ts)는 기존 CLI를 새 Node 프로세스로 호출한다. 합성 root를 `.fragment-test/content-workspace-*`에 만들며, 실제 운영 콘텐츠·원래 폴더의 변경·Git 승인 자료를 시험용으로 사용하지 않는다. 정리는 소유한 임시 root의 경계를 확인한 뒤 수행한다.

| 검사 사례 | 실제 확인한 결과 |
| --- | --- |
| 작업 두 건과 재실행 | 서로 다른 요청 폴더에서 두 글을 적용한 뒤 apply/plan 재실행은 unchanged. 기존 HANDOFF·초안·메모·요청·계획·개발 STATUS/로그 파일의 바이트·mtime 보존 |
| 한 작업의 여러 요청 | 카테고리 생성→글 생성→제목 후속 수정의 개별 입력·계획·완료 기록 유지. 이전 요청 원문·다른 기록 보존 |
| 오래된 HANDOFF | 미적용 메모가 남아도 실제 완료 요청은 unchanged. 완료 메모가 있어도 실제 파일의 외부 수정은 receipt.state-mismatch로 거절하고 보존 |
| 같은 ID·다른 입력 | 별도로 준비한 다른 입력은 request.conflict로 거절. 원래 요청과 실제 파일 보존 |
| 다른 사본과 준비 자산 | 요청/계획만 복사하면 자산 누락으로 실패. 자산 원문을 전달하고 명시적 root를 지정하면 수신 사본에만 적용. 다른 cwd에 있는 원래 사본은 보존 |
| 수신 사본의 다른 기준 | 전송된 수정 요청이 수신 파일의 편집을 baseline.conflict로 거절. 양쪽 원문 보존 |
| 중단 저널 없는 recover | 작업공간 안 요청/계획 경로로 실제 recover를 호출해 recovery.missing 거절 확인. 복구 자료를 만들어내거나 파일을 변경하지 않음 |

위 두 사본은 같은 컴퓨터의 독립 임시 폴더다. 실제 다른 컴퓨터·Git worktree의 이동·사용자 계정 연동을 시험한 것은 아니다. 새 대화 세션 인계는 보존한 요청을 읽는 새 CLI 프로세스로 모사했고, 모든 AI가 지시문을 올바르게 해석했다는 평가로 확대하지 않는다.

기존 잠금·강제 중단·복구·다른 호스트/불명 소유자·손상/외부 변경의 거절은 기존 복구 통합 41개를 포함한 전체 회귀로 확인했다. 새 recover 사례는 중단 자료가 없는 경우의 거절이며, 실제 중단 재개 검증은 기존 회귀의 증거와 구분한다. Git 승인·실제 tree·공통 CI 통합 22개도 전체 회귀에 포함된다.

## 검사 실행과 버전별 증거

| 범위 | 결과 |
| --- | --- |
| 신규 작업공간 실제 CLI | 7개 통과 |
| 전체 단위·통합 | 33파일 616개 통과, 생략 없음. 선행 609개에 신규 7개 추가 |
| 최종 타입 | 127파일 오류 0·경고 0·기존 힌트 5 |
| 선행 템플릿 문서 | YAML 4블록·문서 명령 3개 기존 파서 호환성·상대 링크 검사 통과 후 사용자 통과 |
| 선행 원격 CI | 정확한 ACWT01 `454f9739fcd9f7f70eb25b7a10683466a98fb5e6`의 [Actions](https://github.com/avocadosmasher/avocadosmasher.github.io/actions/runs/39425342872) 성공 |

최종 전체 검사는 `npm test -- --reporter=dot`, 타입 검사는 `npx astro check`로 실행했다. 신규 사례만 확인할 때는 `npx vitest run tests/integration/content-workspace.test.ts --reporter=dot`를 사용한다. 사용자가 이 명령을 다시 실행해야 하는 수동 테스트는 아니다.

ACWV01에서 실행 프로그램·웹 화면·Astro 빌드 입력을 바꾸지 않았으므로 일반/격리 Astro 빌드와 브라우저 검사를 중복 실행하지 않았다. 동일 실행 코드가 있는 선행 커밋의 원격 CI 성공과 현재 추가 검사의 로컬 616개 결과를 구분한다. 현재 ACWV01의 원격 결과는 아직 실행된 것으로 표시하지 않는다.

첫 신규 검사 실행은 5개 통과·2개 실패였다. 실제 제목은 YAML 인용 문자열이었는데 단순 텍스트 표현을 가정했고, 변경 입력의 거부 코드를 plan.changed로 잘못 가정했다. 제목의 실제 YAML 값과 기존 request.conflict 계약을 확인하도록 새 검사 준비를 고친 뒤 7개·전체 616개가 통과했다. 기존 테스트·기능 기대값은 변경하지 않았고, 기존 동작의 호환성 검사를 새 기능 Red로 계산하지 않았다. 추가한 미사용 import도 정리해 기존 타입 힌트 5개를 유지했다.

## 보장과 미보장

| 영역 | 확인한 범위와 한계 |
| --- | --- |
| 기록 분리 | Tool은 지정한 콘텐츠/기록만 반영하고 예시 진행 파일을 보존함. 다른 스킬이 루트 파일을 직접 덮어쓰는 권한 자체는 제한하지 않음 |
| 확정 원문 | 원래 요청·계획을 보존하면 같은 입력을 재실행·대조 가능. 원문을 잃고 해시만 남으면 본문·자산 재생성 불가 |
| HANDOFF | 의도·미결 사항·다음 행동을 기록함. 자동 상태 DB·승인 인증·실제 적용 결과의 대체물이 아님 |
| 동시 작업 | 한 초안/인계 파일의 작성 담당과 지정 worktree를 지키는 협업 정책. 실제 직접 편집 잠금·전역 worktree 잠금·동시 Git 인덱스 격리 아님 |
| local 보관 | Git 제외 평문일 수 있음. 다른 환경에는 필요한 원문·자산을 명시적으로 전달해야 함. 자동 공유·암호화 기능 없음 |
| 복구 | 원래 요청/계획·정상 준비 자료와 지원되는 소유자 상태에서 기존 복구 가능. 다른 호스트·손상·외부 수정·중단된 recover 점유 자체 자동 해결 미지원 |
| 파일 쓰기 | 마지막 기준 확인과 rename 사이 외부 쓰기 원자 차단·완전한 다중 파일 트랜잭션 미보장 |
| 승인·공개 | 사용자 통과·Git 저장·운영 공개 별도. 인계 승인 문구와 CI 성공은 현재 변경의 사용자 판정이 아님 |

외부 스킬 패키지·원래 프로젝트 폴더의 별도 스테이징 삭제 3건·실제 블로그 원문·기존 URL/ID·기존 Infra 예외는 변경하지 않는다. main 병합·Pages 배포·운영 OAuth 저장·브랜치 보호 설정은 수행하지 않았다.

## 계획의 완료 기준과 다음 행동

[확정 계획](./plan/AI-콘텐츠-작업공간-분리-개발계획.md)의 공통 규칙 분리, 작업/요청 수명 분리, 스킬 메모·인계 안내, 기존 CLI/receipt/복구/승인 호환성, 실제 검증 증거·미보장 공개에 대한 자료를 마련했다. 경로를 고정 사용하는 스킬의 통제와 모든 AI의 준수는 구현한 기능으로 표시하지 않는다.

ACWV01은 화면·외부 계정 흐름을 바꾸지 않으며 직접 실행할 사용자 테스트가 없다. 현재 마감 자료가 명시적으로 통과하면 기존 승인 기록 후 동일 검토 트리를 개발 브랜치에 커밋·push한다. 이후 main 반영·운영 공개는 별도 결정이다. 완료한 작업을 새 세션에서 중복 등록하지 않도록 실제 대화·Git 저장 증거를 확인한다.
