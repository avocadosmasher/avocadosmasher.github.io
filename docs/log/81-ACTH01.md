- 문제·요청: 승인만으로 콘텐츠 정책 오류가 저장될 수 있으며 작업 폴더로 검사하면 실제 스테이징/전송 Git 대상과 달라질 수 있어 해당 Git tree를 검사하는 Hook·공통 CI 연결 필요함.
- Red: 기존 실제 pre-commit이 스테이징된 미등록 카테고리를 허용하는 assertion 실패 후 Git tree 사본 검사 연결함. 공통 CI 검사 명령 부재 assertion 실패 후 두 단계를 추가함. 추가로 실제 저장소의 훅 실행 권한 100644를 확인하고 Linux에서 누락되지 않도록 100755 요구 assertion 실패 확인함.
- 수정: 기존 승인기는 변경하지 않고 공통 실행기가 먼저 호출함. commit은 실제 인덱스, push는 stdin의 전송할 각 고유 tree를 검사함. 임시 사본에는 정책에 필요한 Git 바이트만 내보내며 링크/submodule은 거절함. PR/개발 push/배포 공통 verify에 콘텐츠 정책·실제 처리 도구 격리 빌드 추가함. Windows에서 실행 권한은 Git 인덱스 속성이므로 해당 훅 두 개의 실행 권한을 우선 등록 후 검증함. 다른 파일의 스테이징은 최종 검사·기록 후 수행 예정임.
- 자동 검사: 최종 신규 Git/CI 통합 22개 포함 전체 608개·32파일 통과함. 실제 합성 저장소 commit/로컬 bare push로 승인 누락/변경·유효 대상·다른 HEAD/인덱스/작업 폴더·다중 참조 stdin·삭제 참조·링크/submodule·한글/공백 경로·Fragment 중복 ID·카테고리 제거·정확한 예외·미수집 평면 글·필수 설정 누락·100755 등록 검사함. 타입 126파일 오류 0·경고 0·기존 힌트 5 확인함. 일반 빌드 11페이지·18이미지 성공함. 네 대상 실제 CLI/격리 빌드 회귀 통과함. 현재 콘텐츠 검사 오류 0·기존 Infra 예외 4·미사용 예외 0 확인함. - 실제 대상 확인: 2026-10-20 현재 개발 브랜치 HEAD의 tree `22fed5d6191c3ad87d227afb71f3644ca3168c4a`를 새 사본 검사기로 읽기 전용 검사해 오류 0 확인함. Node에서 자식 Git 실행이 필요한 사본 검사는 권한 환경을 명시해 실행함. 실제 승인·인덱스·사용자 파일 변경 없이 자기 임시 사본만 정리함. STATUS 최종 갱신일은 마감 날짜로 갱신함.
- 실패 추적: 첫 합성 저장소 준비에서 기존 승인기가 최초 HEAD를 요구해 빈 부모 Git 객체를 준비함. 준비 실패는 기능의 Red로 세지 않음. Git이 커밋 훅 출력을 stderr로 전달하므로 출력 채널 가정을 보완했으며 허용/차단 기대값은 유지함. 선택 실행의 미선택 사례와 달리 최종 전체 실행에는 생략된 사례 없음.
- 사용자 확인: 화면·외부 계정 흐름 변경 없이 실제 로컬 프로세스·Git 파일 결과·종료 코드·YAML 구조로 판정 가능한 범위여서 직접 실행 항목 없음. Git 대상과 작업 폴더 구별·원래 승인 유지·공통 CI·실행 권한·원격 확인 시점을 가이드에 정리함. 현재 변경 통과 전 승인·커밋·push하지 않음.
