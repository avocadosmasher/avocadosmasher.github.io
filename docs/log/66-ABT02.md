# ABT02: 카테고리·프로젝트 이력 작성 템플릿 (2026-10-13, 통과)

- 판정·저장: 사용자 명시적 통과 후 승인 기록·커밋 `f0f58ca`·개발 브랜치 push 완료. 이 상태 갱신은 ABV01 검토 범위다.

- 시작 기준: `0fdfab2`. 사용자가 ABT01 파일 8개를 통과로 판정했다. 승인 훅을 통과해 커밋하고 개발 브랜치 push를 확인했다. 선행 상태 갱신은 이번 ABT02 검토 범위에 포함한다.
- 문제·요청: 카테고리·프로젝트 이력은 consts.ts의 설정·배열 항목을 수정하므로 다른 AI가 전체 설정을 덮어쓰거나 새 ID를 추가할 수 있다. 계획 ABT02에 따라 현행 데이터 형태의 항목 틀과 신규·수정의 대상 확인을 안내한다.
- Red: 템플릿·문서 작업이므로 억지 실패 테스트를 만들지 않았다. 완료 기준은 현행 CATEGORIES와 ProjectItem 구조에 맞는 입력, 기존 대상 식별·보존, 신규와 수정의 구분을 제공하는 것이다.
- 수정: category.json과 project.json을 추가했다. JSON 틀은 값 전달용이고 실제 반영 위치는 consts.ts라고 안내했다. 선택 문자열의 미제공 처리, 빈 배열로 기존 값 삭제 금지, 원래 항목 값 대조·명시적 수정·기준 충돌·프로젝트 이력과 개발 로그 구별을 README에 추가했다. 지시문에서 실제 파일을 안내하고 ABT01 통과 증거를 README·STATUS·메뉴판·결정 기록에 반영했다.
- 자동 검사: JSON 2개를 strict JSON 및 중복 키 검사로 읽고 카테고리 키·색상 한 쌍을 확인했다. 실제 consts.ts를 TypeScript AST로 읽어 ProjectItem 필드·필수 여부·문자열/문자열 배열 타입과 템플릿을 대조해 통과했다. 새 ID 필드가 없고 신규 치환 표시 7개가 모두 안내에 있음을 확인했다. 문서 링크 19개, ABT02 로그·메뉴판 각 1건, ABT01 통과 증거, 문구 검사, `git diff --check` 및 `git diff --cached --check` 통과. 스테이징은 이번 파일 8개뿐이며 미스테이징 변경은 없다. ABT01의 HEAD와 원격 SHA 일치, 소스·콘텐츠·훅 변경 없음, 원래 폴더의 스테이징 삭제 3건 보존을 확인했다. JSON은 자동 로딩하지 않는 값 전달 자료이고 실제 앱 코드를 바꾸지 않아 빌드·타입·단위·E2E는 재실행하지 않았다.
- 사용자 확인 준비: README와 category.json·project.json을 기본 연결 프로그램으로 열었다. 값 전달 방식과 대상 확인 안내의 사용성이 판단 대상이며 자동 검사나 diff 확인을 사용자에게 맡기지 않는다.
- 남은 제약: 현재 PROJECTS에 ID를 추가하거나 설정 분리·자동 JSON 로딩·수정 엔진을 구현하지 않았다. 사이트 색상·운영 콘텐츠·소스·훅은 변경하지 않았다. 실제 데이터 계약과 격리 재실행은 다음 ABV01·ABV02에서 검증한다.
