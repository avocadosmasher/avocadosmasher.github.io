# D08 — 로그인한 작성자의 카드 조회에 토큰 사용 (2026-09-24, 수동 판정 대기)

- 시작 기준: D06·D07 `2528a27`을 사용자 통과 후 커밋·push하고, PR #5를 Merge commit `366c6b2`로 병합했다. 배포 성공 후 초안 브랜치를 `main`과 동일하게 맞췄다(compare identical).
- 사용자 보고: 새로고침하면 발행 전 카드가 카드 목록에서 사라지고 발행 대기 목록에만 보인다.
- 원인: 카드 목록 조회(`loadFragmentSnapshot`)가 토큰 없이 익명으로 GitHub API를 호출했다. 익명 한도는 IP당 시간당 60회이고 카드 수만큼 blob을 읽으므로 금방 소진된다. 한도에 걸리면 조회가 실패해 화면이 빌드 시점의 공개본으로 남는다. 발행 대기 목록은 토큰을 쓰므로 정상 동작해, 둘의 내용이 어긋나 보였다.
- Red: `tests/draft/publish.spec.ts`에 인증 헤더가 없는 요청만 403(rate limit)으로 돌려주는 상황을 추가해, 새로고침 후 초안 카드가 사라지는 것을 재현했다.
- 수정: 로그인 상태이면 카드 조회에도 세션 토큰을 붙인다. 비로그인 방문자는 종전처럼 익명으로 읽고, 실패하면 빌드 스냅샷을 그대로 보여 준다.
- 자동 검사: `npm run check` 오류 0, `npm test` 99개, `npm run build` 12페이지, `npm run test:e2e:preview` 8개, `npm run test:e2e` 8개, `npm run test:h01` 4개, `npm run test:oauth` 34개, `npm run test:admin` 4개, `npm run test:draft` 15개 통과, `git diff --check` 통과.
- 미확인: 운영에서의 실제 동작. 배포 후 사용자가 인수한다. 지난 보고의 "배포 상태 미표시"도 같은 익명 한도가 원인일 수 있으나, 배포 상태 조회는 원래 토큰을 사용하므로 별개다. 실패 사유 표시(D07)로 다음 확인 때 판별한다.
- 사용자 요청(같은 작업 중): "최신 카드 다시 불러오기" 문구 버튼이 눈에 거슬린다 → 카드 보기/관계 그래프 옆으로 옮기고 아이콘 형태로.
  - 세 시안을 캡처해 비교했다: A 아이콘만 독립 버튼, B 아이콘+"새로고침" 글자, C 전환 버튼 안쪽 구분선. 사용자가 **B**를 선택했다(`.fragment-test/refresh-*-1280.png`).
  - 버튼은 뷰 전환과 같은 높이·모서리를 쓰고 아이콘은 직접 그린 원형 화살표다. 불러오는 동안 회전하며 잠기고(동작 줄이기 설정에서는 회전 없음), 실패해도 사라지지 않는다. 예전에는 실패했을 때만 나타났다 사라졌다. 비로그인 방문자에게는 보이지 않는다.
  - 안내 문구를 "잠시 후 다시 불러와주세요"에서 "다시 불러오기를 눌러주세요"로 맞췄다. 최종 화면은 `.fragment-test/refreshB-desktop.png`, `.fragment-test/refreshB-mobile.png`.
- 관련 파일만 스테이징하고 판정을 기다린다. 승인 명령·커밋·push는 실행하지 않았다.
