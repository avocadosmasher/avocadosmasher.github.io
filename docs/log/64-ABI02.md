# ABI02: 요청서·세션 인계·완료 보고 지시문 (2026-10-13, 판정 대기)

- 시작 기준: `fd6d085`. ABI01 문서 6개에 명시적 통과 판정을 받아 승인 훅을 통과해 커밋·개발 브랜치 push했다. 선행 상태 갱신은 이번 검토 범위에 포함한다.
- 문제·요청: 다른 세션·AI로 요청을 넘길 때 원래 대상·확정 내용·기준 상태·실제 저장 결과가 빠지면 신규 항목을 다시 만들거나 미확인 쓰기를 완료로 보고할 수 있다. 계획 ABI02에 따라 요청·인계·완료 보고 형식을 작성한다.
- Red: 문서 작업이므로 억지 실패 테스트를 만들지 않았다. 완료 기준은 저장소와 웹 접근에서 실행 가능한 절차, 누락·미지원 작업 처리, 판정 대기와 실제 확인된 단계의 보고를 제공하는 것이다.
- 수정: 공통 지시문·YAML 요청서·접근 경로별 지시·글과 웹 Fragment 요청 예시·미지원 웹 프로젝트 인계·중단 및 응답 유실 인계·단계별 보고 형식을 추가했다. 인계용 메타데이터를 콘텐츠 frontmatter로 쓰지 않도록 구분하고, 요청 단계와 실제 승인도 분리했다. 원본 조회로 AI가 채울 수 있는 정보는 사용자에게 일괄 질문하지 않도록 안내했다. 규약에서 실제 지시문으로 연결하고 ABI01 통과·push 증거를 STATUS·메뉴판·결정 기록에 반영했다.
- 자동 검사: YAML 예시 4개를 기존 yaml 라이브러리로 읽어 문법·중복 키·요청 식별자 검사를 통과했다. 문서 링크 23개, ABI02 로그·메뉴판 각 1건, ABI01 통과 증거, 문서 변경 범위를 검사해 통과했다. 문구 검사에서 비한국어 혼입을 발견해 정정하고 재검사했다. `git diff --check` 및 `git diff --cached --check` 통과. 스테이징은 이번 문서 6개뿐이며 미스테이징 변경은 없다. ABI01의 HEAD와 원격 SHA 일치, 소스·콘텐츠·훅 변경 없음, 원래 폴더의 스테이징 삭제 3건 보존을 확인했다. 문서만 변경했으므로 타입·단위·빌드·E2E는 재실행하지 않았다. 예시 문법 검사와 실제 저장·재실행 검증을 구별했다.
- 사용자 확인 준비: AI 콘텐츠 작업 지시문 파일을 기본 연결 프로그램으로 열었다. 공통 요청서와 경로별 지시문, 인계 기록의 사용성이 판단 대상이다. 자동 검사나 diff 확인을 사용자에게 맡기지 않는다.
- 남은 제약: 형식 안내이며 자동 파서·처리 명령·요청 이력 저장소를 구현하지 않았다. 예시를 실제 운영 저장이나 멱등성 실행 증거로 사용하지 않는다. 실제 파일 템플릿은 ABT01·ABT02, 데이터 계약·격리 재실행 검증은 ABV01·ABV02의 범위다. 운영 콘텐츠·소스·웹 기능·훅을 변경하지 않았다.
