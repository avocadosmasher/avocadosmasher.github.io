- 문제·요청: 문서·템플릿만으로 실제 적용/인계 결과를 보장할 수 없어 확정 계획의 작업 분리·개별 요청·재실행·오래된 메모·원문/자산 인계를 실제 CLI와 기존 회귀로 확인할 필요 있음.

- 실제 시나리오: 두 작업의 HANDOFF/초안/메모·기존 요청/계획·개발 STATUS/로그를 보존하며 적용/재실행함. 한 작업의 카테고리 생성→글 생성→후속 수정을 서로 다른 요청으로 보존함. 오래된 미적용 메모여도 실제 완료 요청은 unchanged, 완료 메모여도 외부 수정은 receipt.state-mismatch로 거절함. 같은 ID의 다른 입력은 원래 입력 보존 후 request.conflict로 거절함. 다른 사본은 자산 누락 시 실패하고 원문 전달/명시적 root 뒤 그 사본에만 적용함. 다른 기준과 저널 없는 recover는 거절하고 파일 목록·바이트·mtime을 보존함.
