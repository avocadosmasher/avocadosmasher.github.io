# ACTV02: 전체 관계·등록 카테고리·기존 예외 검사 (2026-10-16, 판정 대기)

- 시작 기준: ACTV01 명시적 통과 후 기존 승인 기록·커밋·개발 브랜치 push 완료 확인함. 기준 커밋 `7a37ee1`임. 선행 작업의 통과 상태는 이번 검토 범위에서 갱신함.
- 문제·요청: 문서별 형식 검사만으로 서로 다른 파일의 중복 ID·없는 관계 대상·관계 쌍 중복·미등록 카테고리를 확인할 수 없음. 기존 Infra 4건을 보존하면서 새 위반을 구별할 필요가 있음.
- Red: 신규 카테고리·중복 ID·없는 대상·자기 참조·방향/유형이 다른 관계 쌍 중복에서 실제 assertion 실패 확인 후 차례로 구현함. 정확한 기존 예외가 차단되는 실패·입력 순서에 따른 진단 변화·null 예외 설정의 묵인·같은 경로 중복 입력의 허용도 Red에서 Green으로 수정함. 첫 테스트는 실행 완료 수집 전에 최소 모듈을 작성했으므로 모듈 부재 실패로 기록하지 않고 실제 카테고리 assertion 실패를 근거로 삼음.
- 수정: 전체 문서 집합을 받는 순수 검사 모듈·명시적 예외 JSON 추가함. 기존 단일 문서 검사와 frontmatter 분리 함수를 공유함. 예외의 규칙·경로·값이 모두 일치해야 허용함. 예외 발생·미사용 예외를 결과에 구분함. 불완전한 Fragment 집합에서는 관계 검사 미수행 상태를 반환함. 입력 순서를 정렬한 복사본으로 처리하며 원문은 수정하지 않음.
- 자동 검사: 새 단위 34개·실제 콘텐츠 통합 1개 포함 전체 212개 통과함. 타입 검사 오류 0·경고 0·기존 힌트 5 확인함. 일반 빌드 11페이지·18이미지 성공함. 실제 수집 대상 글 13개·Fragment 3개의 실패 진단 0건·기존 예외 4건·미사용 예외 0건 확인함. 콘텐츠·예외 파일 바이트 보존 검증함. Graft 75개 소스 갱신함. 전체 테스트는 샌드박스의 esbuild 실행 제한으로 한 번 시작 실패한 뒤 권한을 높여 통과함. 타입 검사는 출력 지연 후 완료 확인했고 권한을 높인 재실행도 동일 결과임.
- 마감 검사: 문서 6개의 상대 링크 16개·ACTV02 메뉴판 단일 항목·한국어 문구 검사 통과함. 운영 콘텐츠·CATEGORIES·기존 스키마·훅·CI·패키지 설정의 변경 없음 확인함. 원래 폴더의 스테이징 삭제 3건도 유지 확인함. 이번 작업 파일 13개만 스테이징 대상으로 지정함. 화면·저장 흐름은 바꾸지 않아 브라우저 E2E와 ACTV01의 격리 빌드 4건을 반복하지 않음.
- 사용자 확인 준비: 진단 사례·예외 경계·현재 보장 범위를 설명하는 구현 현황 문서를 기본 앱으로 열었음. 새 UI나 CLI가 없으므로 사용자에게 자동 검사 실행·코드 diff 검토를 요청하지 않음. 기존 자료 보존과 새 위반 차단 기준의 판정만 요청함.
- 남은 제약: 문서 수집·정적 설정 읽기·종료 코드를 갖춘 CLI는 ACTC01 범위임. Hook·CI 저장 차단·로컬 적용·재시도 보장은 이후 작업임. 예외 목록의 인증·권한 통제는 구현하지 않음. 기존 승인 훅·배포·운영 콘텐츠·CATEGORIES는 변경하지 않음. 원래 폴더 삭제 3건은 보존함.
