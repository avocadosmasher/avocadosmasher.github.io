# ABV02: 세션 인계와 재실행 절차의 격리 검증 (2026-10-14, 판정 대기)

- 시작 기준: `9a84ac9`. 사용자의 ABV01 명시적 통과 후 검토한 트리 그대로 승인 기록·커밋·개발 브랜치 push 성공을 확인했다. 이전 상태 갱신은 이번 ABV02 검토 범위다.
- 문제·요청: 다음 세션이 확정 입력·실제 ID·기준 원문을 잃으면 중복 작성·덮어쓰기·오인 보고가 생길 수 있다. 계획 ABV02에 따라 격리 파일의 인계·동일 입력 재실행·필드 보존·충돌·미지원 웹 작업 인계를 확인한다.
- Red: 최초 검증 보조 모듈 부재 실패를 기록했다. 파일 기반 모의 API는 기존 앱 함수의 동작을 특성 검사하며 기능 결함 Red라고 주장하지 않는다. 새 인계 보호에서는 같은 요청 ID의 확정 입력 파일이 달라져도 예외를 던지지 않는 assertion 실패를 확인했다. 원문 지문 대조로 입력 충돌을 차단해 Green을 확인했다.
- 수정: 격리 파일 저장소와 모의 API, 인계 YAML 참조·확정 입력 SHA-256 대조, 실제 Fragment 저장·재시도·SHA 충돌·입력 보존 검사와 다른 콘텐츠의 참조 절차 시나리오 13개를 추가했다. 신규 생성·제목 변경·응답 유실·조회 실패·제목 모호성·글/자산·카테고리·프로젝트·웹 미지원 인계를 확인한다. 지시문의 선택적 원문 지문과 사용자 판정 증거 구별을 안내했다. 일반 작성 엔진과 운영 쓰기는 구현하지 않았다.
- 자동 검사: 관련 시나리오 13개와 기존 전체 단위·통합을 합친 135개 통과. 타입 검사 오류 0·경고 0·기존 힌트 5. 파일 차이는 모든 격리 파일의 SHA-256, 추가 쓰기는 횟수로 검사했다. 문서 링크 25개·YAML 예시 4개·ABV02 메뉴판 단일 항목·diff 공백 검사 통과. 한글 경로가 PowerShell 표준입력의 인코딩으로 깨진 문서 검사 준비 오류는 경로를 명령 인자로 넘겨 해결했다. Graft 68개 소스를 갱신했다. 원래 폴더의 스테이징 삭제 3건은 유지하고 이번 파일 11개만 스테이징한다. 앱 소스·콘텐츠·빌드 설정 변화가 없어 ABV01의 실제 빌드 4건·일반 빌드를 재실행하지 않았다. UI 변화가 없어 E2E도 재실행하지 않았다.
- 사용자 확인 준비: 새 인계 검증 결과와 지시문을 기본 앱으로 연다. 판단할 내용은 실제 자동 보장과 규약을 재현한 절차의 구분, 원문 지문이 승인 증거를 대신하지 않는 인계 방식이다. 자동 검사 실행·diff 확인·실제 운영 저장을 요청하지 않는다.
- 남은 제약: 실제 AI의 다른 채팅 세션 실행·지시 준수율이나 미지원 웹 작업의 자동 라우팅을 검증한 것이 아니다. 웹에서 발급된 ID를 응답 유실 뒤 모르는 상태의 자동 중복 방지도 증명하지 않는다. 원문 지문은 선택적 인계 자료이며 운영 앱에서 자동 검사하는 기능이 아니다. 운영 OAuth·외부 서비스 쓰기·main 배포는 수행하지 않았다. 최종 운영 안내·1차 완료 증거는 다음 ABA01에서 정리한다.
