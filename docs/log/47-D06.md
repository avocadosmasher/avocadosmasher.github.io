# D06 — 새로고침 후 발행 대기 표시와 배포 완료 자동 반영 (2026-09-21, 수동 판정 대기)

- 시작 기준: D03 `cb1ee60`을 사용자 통과 후 커밋·push하고, PR #4를 Merge commit `24cbc41`로 병합했다. 배포 성공을 확인하고 초안 브랜치를 `24cbc41`에 맞췄다.
- 사용자 보고 2건(운영 사이트): (1) 새로고침하면 발행 대기가 화면에 반영되지 않는다, (2) 배포가 끝나도 문구가 바뀌지 않고 새로고침해야 한다. GitHub Pages의 한계가 아니라 화면 쪽 로직 문제였다.
- 원인
  - (1) 발행 영역은 작성 창 스크립트가 로그인 복원을 마친 뒤 보내는 `fragment-session` 이벤트에만 의존했다. 두 스크립트의 로딩·네트워크 타이밍에 따라 목록 쪽이 그 이벤트를 놓칠 수 있다.
  - (2) 발행 직후 배포 상태를 읽는데, 그 시점에는 방금 만든 커밋의 실행이 아직 큐에 없어 **직전 실행**이 잡힌다. 직전 실행이 완료 상태면 추적을 그대로 멈춰 이후 변화가 반영되지 않았다.
- Red: `tests/draft/publish.spec.ts`에 2개를 추가했다. 권한 확인 응답을 1.5초 지연시킨 뒤 새로고침해도 대기 목록이 보여야 하고, 발행 후 직전 실행이 완료 상태여도 새 커밋의 실행을 기다렸다가 완료로 바뀌어야 한다. 두 번째는 수정 전 실패를 확인했다(첫 번째는 이 방식으로 재현되지 않았지만 의존 자체를 없앴다).
- 수정
  - `src/scripts/fragments.ts`가 로드 시 `loadSession`으로 저장된 로그인을 직접 읽어 발행 영역·대기 목록·배포 상태를 바로 표시한다. 이벤트는 로그인/로그아웃 전환용으로만 남는다.
  - 발행에 성공하면 그 병합 커밋 SHA를 기억하고, 실행의 `head_sha`가 그 커밋이 될 때까지 "배포 중"으로 두고 5초 간격으로 기다린다. 해당 실행이 시작되면 15초 간격으로 완료까지 따라간다. 완료되면 대기 목록과 카드 목록도 다시 불러온다.
- 자동 검사: `npm run check` 오류 0, `npm test` 99개, `npm run build` 12페이지, `npm run test:e2e:preview` 8개, `npm run test:e2e` 8개, `npm run test:h01` 4개, `npm run test:oauth` 34개, `npm run test:admin` 4개, `npm run test:draft` 12개 통과, `git diff --check` 통과.
