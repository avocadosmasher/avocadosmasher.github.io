# ACTS01: 동시 적용 잠금·중단 복구 (2026-10-19, 판정 대기)

- 시작 기준: ACTJ01 사용자 명시적 통과 후 검토한 동일 트리를 `f93588e`로 커밋·개발 브랜치 push 완료 확인함. 선행 통과 상태는 이번 작업에서 갱신함. 원래 폴더의 스테이징 삭제 3건은 별도 보존함.
- 문제·요청: 동시 적용과 다중 파일 부분 저장을 완료로 오인할 수 있어 저장소 적용 잠금·쓰기 전 준비 자료·원래 계획 기준의 명시적 복구 필요함.
- Red: 기존 apply가 살아 있는 잠금을 무시하던 assertion 실패 → 프로젝트 진입점 잠금 최소 구현함. 교체 실패 뒤 저널 부재 assertion 실패 → 사전 준비 바이트·완성 저널 게시 구현함. recover CLI 미지원 실패 → 요청/계획/기대 지문 필수 명령 구현함. 종료된 같은 호스트 소유자 잠금 회수 실패 → 배타적 복구 점유·종료 재확인 구현함. 기존 어댑터의 성공·충돌·무변경 결과는 회귀로 유지하며 기대값을 완화하지 않음.
- 수정: 다섯 적용 진입점을 공통 저장소 잠금·준비 자료로 감쌈. 최종 바이트·최소 지문 저널을 콘텐츠 쓰기 전에 준비하고 미완료 저널은 새 적용을 중단시킴. recover는 원래 요청/계획/지문·실제 전후 상태·준비 바이트·현재 제안 정책 대조 후 남은 파일과 기록만 반영함. 이미 반영된 파일·사용자 외부 수정·손상 파일 보존함. 완료된 결과는 로컬 자료만 정리함. 살아 있는/원격/불명확한 소유자와 남은 복구 점유를 강제 해제하지 않음. 기존 버전 1 요청·계획·공유 기록 유지하며 recover 인자와 필요 시 recovery/cleanup_pending/lock_release만 추가함.
- 자동 검사: 신규 복구 통합 41개 포함 최종 전체 586개·31파일 통과함. 실제 두 CLI의 동시 진입 차단·후속 오래된 계획 충돌 확인함. 실제 프로세스를 I/O 경계에서 강제 종료해 글/자산 부분 생성·Fragment 관련 파일 부분 수정·완료 기록 후 응답 유실을 복구함. 완료 파일 바이트·mtime 보존 확인함. - 사용자 확인: 화면·운영 계정 흐름 변경 없이 파일/종료 코드·실제 프로세스 실험으로 판정 가능한 범위여서 직접 실행 항목 없음. 잠금·복구 동작과 실제 예시·보관 경계·거절 조건·미지원 범위를 가이드에 정리함. 기존 AGENTS에 따라 현재 변경의 통과 판정 전 승인·커밋·push하지 않음.
