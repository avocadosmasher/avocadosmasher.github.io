# D07 — 발행 대기 표시 정정과 배포 상태 실패 노출 (2026-09-21, 수동 판정 대기)

- 사용자 보고(운영, PR #4 배포본): 발행할 것이 없는데 "발행 대기 2건"으로 표시되고, 목록 보기 버튼은 나오지 않으며, 배포 기록이 화면에 전혀 없다.
- 조사: `compare main...fragments-draft`는 `ahead 2 / behind 1 / files []`였다. 두 커밋은 "카드 생성"과 "그 초안 제거" 한 쌍이라 내용 차이가 없다. `main`의 추가 커밋 `a610b2b`는 사용자가 앞서 발행한 카드 2개 삭제다. 배포 실행 기록은 저장소에 32건 존재한다.
- 원인
  - 카드 파일 변경이 0일 때 커밋 수(`ahead_by`)를 대신 표시해 "발행 대기 2건"이 나왔다. 목록 버튼은 카드 변경 기준이라 숨겨져, 표시가 서로 어긋났다.
  - 배포 상태 조회가 실패하면 줄을 숨기도록 해 두어 화면에 아무것도 남지 않았고 사유도 알 수 없었다.
- 수정
  - 발행 대기는 카드 파일 변경만으로 판단한다. 변경이 없으면 "발행할 변경이 없습니다."를 표시하고 발행 버튼도 숨긴다. 내용 없는 커밋은 다음 발행에 함께 합쳐지며 사이트에는 영향이 없다.
  - 배포 상태 조회 실패 시 "배포 상태를 확인하지 못했습니다."와 사유를 보여 주고, 저장소의 배포 기록 페이지 링크를 남긴다. 실행이 하나도 없으면 "아직 배포 기록이 없습니다."로 구분한다.
- Red: `tests/draft/publish.spec.ts`에 2개를 추가해 수정 전 실패를 확인했다(카드 변경 없는 커밋 2건, 조회 403).
- 자동 검사: `npm run check` 오류 0, `npm test` 99개, `npm run build` 12페이지, `npm run test:e2e:preview` 8개, `npm run test:e2e` 8개, `npm run test:h01` 4개, `npm run test:oauth` 34개, `npm run test:admin` 4개, `npm run test:draft` 14개 통과, `git diff --check` 통과.
- 남은 확인: 운영에서 배포 상태 조회가 왜 실패했는지는 아직 모른다. 이번 변경으로 실패 사유가 화면에 남으므로 다음 확인 때 알 수 있다.
