# ACTF01: Fragment 생성·부분 수정·관련 관계 계획 (2026-10-19, 판정 대기)

- 시작 기준: ACTB02 명시적 통과 후 승인 트리를 그대로 `736c11a`로 커밋·개발 브랜치 push 완료 확인함. 선행 통과 상태는 이번 작업에서 갱신함. 원래 폴더의 스테이징 삭제 3건은 별도 보존함.
- 문제·요청: 글 도구만으로 Fragment를 처리할 수 없고 카드 재생성·ID/경로 변경·미요청 필드 손실·역방향 관계 중복이 생길 수 있어 고정 ID와 실제 파일명을 보존하는 어댑터가 필요함.
- Red: 기존 CLI에서 Fragment 생성 계획·제목만 수정한 원문 보존의 기대 결과 2건 실패 확인함. 공통 편집과 계획 저장을 분리하고 Fragment 어댑터를 연결해 Green 확인함. 관계·재실행·충돌·전체 정책 사례를 추가하고 기존 중복 ID 오류 코드 fragment.duplicate-id 계약을 기대값에 정확히 반영함.
- 수정: 확정 신규 ID·원문·경로 대조, 기존 경로·ID 확인, 요청 필드 값 범위 편집, 전체 제안 정책 검사, 최소 완료 기록과 무변경 재실행을 연결함. changes.relations는 대상 카드의 최종 목록, related_targets는 명시한 상대 카드에서 대상 ID로 들어오는 연결 제거 목록으로 구체화함. 다른 연결·필드·본문을 보존하고 전체 관련 결과를 한 계획으로 검사함. 변하지 않은 카드도 계획·기록에는 포함하되 실제 쓰기·mtime 변경은 생략함. 기존 글 API와 테스트는 유지함.
- 자동 검사: Fragment 신규 통합 39개 포함 전체 429개·28파일 통과함. Astro 검사 111파일 오류 0/경고 0/기존 힌트 5 확인함. 일반 빌드 11페이지·18이미지 성공함. 격리 실제 CLI로 글 생성/수정/각 재실행·두 Fragment 생성/각 재실행·제목과 역방향 관계 제거/새 관계 적용/재실행을 검증함. 실제 Astro 산출물에서 글 제목·본문·이미지·검색과 Fragment ID·제목·관계 확인함. 현재 수집 글 13·Fragment 3 검사 오류 0·기존 예외 4·미사용 예외 0 확인함. Graft 소스 94개 갱신함.
- 사용자 확인: 화면·운영 계정 흐름이 없고 파일 결과·종료 코드로 검증 가능한 범위이므로 직접 실행 항목 없음. 생성·제목 수정·관련 카드 연결 제거의 예시와 현재 한계를 설명한 Fragment 가이드를 기본 앱으로 열었음. 기존 AGENTS의 현재 변경 통과 판정은 유지하며 판정 전 승인·커밋·push하지 않음.
- 마감 확인: 이번 파일 20개·상대 링크 134개·한국어 문구와 인코딩·ACTF01 메뉴판 단일 항목 확인함. 실제 작업 폴더에 .content-ops를 만들지 않았으며 도구 적용은 격리 사본에서만 실행함. 운영 콘텐츠·CATEGORIES·스키마·예외·웹 작성기·OAuth·승인 훅·CI·배포·패키지와 잠금 파일 변경 없음 확인함. 원래 폴더의 스테이징 삭제 3건 보존함. 화면 변화가 없어 브라우저 E2E는 반복하지 않고 실제 Astro 데이터 산출물을 검사함. 이번 작업의 20개 파일만 스테이징 대상으로 지정함.
- 남은 제약: 다중 파일 원자성·외부 쓰기의 완전한 차단·도구 간 잠금·중단 복구·실패 주입은 ACTS01 범위임. 미명시 카드의 관계는 자동 수정하지 않음. 지원 밖 기존 Fragment 필드·앵커 원본/흐름 매핑 메타데이터 수정은 거절함. 카테고리·프로젝트·Hook/CI 저장 차단은 후속 작업임. 운영 콘텐츠·실제 웹 저장 API·OAuth·스키마·예외 목록·승인 훅·배포 설정을 변경하지 않음.
