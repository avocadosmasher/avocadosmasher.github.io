# ABI01: 공통 AI 진입점과 콘텐츠 규약 연결 (2026-10-13, 판정 대기)

- 시작 기준: `1c10699`. ABR02 문서 8개에 사용자의 명시적 통과 판정을 받아 승인 훅을 통과해 커밋·개발 브랜치 push했다. 선행 상태 갱신은 이번 ABI01 검토 범위에 포함한다.
- 문제·요청: AI별 진입 문서가 공통 콘텐츠 규약을 직접 안내하지 않고, AGENTS가 Fragment 전용 커밋 전략을 모든 작업에 적용하는 문장으로 시작해 새 개발 건의 범위가 섞일 수 있었다. 계획 ABI01에 따라 동일 원문으로 연결한다.
- Red: 문서 작업이므로 억지 실패 테스트를 만들지 않았다. 완료 기준은 STATUS에서 규약을 찾고 AGENTS·CLAUDE가 동일 규약을 참조하며 세부 규칙을 중복 복제하지 않는 것이다.
- 수정: STATUS 먼저 읽기와 작업에 필요한 문서 선택을 유지했다. AGENTS·CLAUDE에 공통 규약 링크와 문서 역할을 추가하고 개발 건에 맞는 계획·결정 기록 선택을 안내했다. Fragment 전용 전략은 해당 개발에 적용하도록 범위를 구분했고 공통 완료 절차·Git 훅·파일 열기 선호는 유지했다. 결정 기록에 링크 방식과 복제·통합 대안을 비교했다. ABR02 통과·push 증거를 STATUS·메뉴판에 반영했다.
- 자동 검사: 실제 로컬 링크 10개, STATUS·AGENTS·CLAUDE의 규약 링크가 같은 파일로 해석되는 점, ABI01 로그·메뉴판 각 1건, ABR02 통과 증거, 한국어 문구를 검사해 모두 통과했다. 기존 필수 완료 순서·Git 훅 설명·Graft 블록은 HEAD 원문과 비교해 그대로임을 확인했다. `git diff --check` 및 `git diff --cached --check` 통과. 스테이징은 이번 문서 6개뿐이며 미스테이징 변경은 없다. ABR02의 HEAD와 원격 SHA 일치, 소스·콘텐츠·훅·워크플로 변경 없음, 원래 폴더의 스테이징 삭제 3건 보존을 확인했다. 문서만 변경했으므로 타입·단위·빌드·E2E는 재실행하지 않았다.
- 사용자 확인 준비: AGENTS·CLAUDE·STATUS 파일을 기본 연결 프로그램으로 열었다. 사용자에게는 공통 원문 참조 방식과 안내의 명확성만 판단받고 자동 검사나 diff 확인을 맡기지 않는다.
- 남은 제약: 문서 연결이며 모든 AI 도구의 자동 로딩을 보장하지 않는다. 실제 요청서·인계·완료 보고 형식은 다음 ABI02에서 추가한다. 운영 콘텐츠·소스·훅·UI·외부 서비스에 쓰지 않았고 이전 작업의 판정을 ABI01 승인으로 해석하지 않는다.
