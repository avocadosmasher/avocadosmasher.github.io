# I01 — 운영 가이드 (2026-09-24, 수동 판정 대기)

- 시작 기준: D08과 새로고침 버튼 변경 `8b71ad6`을 사용자 통과 후 커밋·push하고, PR #6을 Merge commit `2c0711d`로 병합했다. 배포 성공 후 초안 브랜치를 `main`에 맞췄다. 사용자가 운영 사이트에서 초안 유지·새로고침·발행·배포 상태 전환이 정상임을 확인했다("잘 되네").
- 이로써 H05(실제 배포와 전체 사용자 흐름)와 D01~D08이 실제 운영에서 동작함을 확인했다.
- 사용자 요청으로 가이드에 두 가지를 반드시 포함했다: (1) 시행착오와 그때의 선택·이유, (2) 구성 요소의 동작 원리(특히 새로 만든 것).
- `../guide/Fragment-운영가이드.md`를 새로 썼다. 기존 `../guide/운영가이드.md`는 블로그 글쓰기 흐름이라 그대로 두고 분리했다.
  - 1장 평소 작업 흐름과 막혔을 때의 대처표.
  - 2장 동작 원리: 브랜치 두 개, OAuth Worker(PKCE·state 서명·Durable Object 10분 세션), 토큰 보관(탭 세션·열 때 권한 재확인), 카드 읽기(빌드 스냅샷 + 실시간 조회, 로그인 시 토큰 사용), 저장·수정·삭제(ID 고정, 버전 비교, 관계 검증, 참조 시 삭제 차단, 응답 유실 복구), 발행 대기 목록과 제거, 배포 상태 추적(발행 커밋 지목), 빌드·배포 게이트, 검사 모음.
  - 3장 시행착오 15건: 전용 편집 UI 전환, 운영 저장소 보호와 명시적 해제, ZIP 업로드 실패 2회, 서명 키 생성 실패, 그래프 성능 대 가독성, 로딩 중 키보드 포커스, 테스트가 운영 카드에 의존해 배포가 막힌 사고와 선택지 비교, 배포 타이밍 3안 비교, 로그인 유지 범위, 발행 대기 개수 오류, 배포 상태 미표시·미갱신, 익명 조회 한도, 한국어 줄바꿈, 새로고침 버튼 시안 선택, 검증 절차 조정.
  - 4장 한계(초안은 공개 저장소에 있음, 토큰 보관 범위, API 한도, 반영까지 3~4분, 연속 발행 시 취소, 로컬 로그인 불가, 비교 API 파일 목록 상한).
  - 5장 설정 위치표(OAuth App, Worker 변수·비밀값, 배포 워크플로 연결, Worker 배포 명령). 비밀값 자체는 적지 않는다.
- 자동 검사: 문서만 변경했다. `npm run check`와 `npm run build`로 기존 상태 유지를 확인했고, 동작 코드 변경이 없어 테스트는 재실행하지 않았다.
- 관련 파일만 스테이징하고 판정을 기다린다. 승인 명령·커밋·push는 실행하지 않았다.
