# R01 — 관계 양방향 표시 (2026-09-24, 판정 대기)

- 시작 기준: K01 `/admin/` 제거가 PR #7로 배포 완료. 사용자가 운영 사이트에서 카드 생성·발행·관계 저장까지 확인한 뒤 제기한 개선 요청.
- 사용자 지적: "비교 개념 같은 건 한쪽에서만 일방적으로 갖는 관계가 아닌데, 지금은 어떤 관계든 한쪽에서만 등록된다."

## 확인한 것

`graft grep`으로 관계를 읽는 모든 지점을 확인했다. **데이터는 이미 양방향 엣지로 다루고 있었고, 읽는 화면 세 곳만 한쪽 방향**이었다.

- 양방향이던 것: 그래프 생성·이웃 탐색(`fragments.ts:108`), 중복 관계 차단(`fragment-relations.ts:16`, `fragment-writer.ts:199`), 삭제 차단(`fragment-writer.ts:218`)
- 한쪽 방향이던 것: 팝업 관계 목록, 카드 푸터 개수, 편집 폼 목록

그래서 "B에서는 관계가 보이지 않는데 B를 지우려 하면 그 관계 때문에 차단되는" 모순이 있었다.

유형별로는 **4개 전부 양방향으로 보여야 하고**, 차이는 반대편에서의 이름뿐이다(관련·비교는 동일, 선행↔후속, 상위↔하위). 선택지 비교와 결정 근거는 `../decision/Fragment-관계-양방향성.md`에 남겼다. 저장 방식은 그대로 두고(한 곳 저장), 읽을 때 합치는 안을 골랐다.

## 이번 단계(R01)에서 한 일 — 표시만

1. `src/lib/fragments.ts`에 `inverseRelationLabels`(후속 개념·하위 개념)와 `cardRelations(cards, id)` 추가. 자기 관계 + 들어오는 관계를 합치고, 들어오는 항목에는 역 라벨과 `inbound: true`를 붙인다. 한 쌍은 한 번만 나온다.
2. 팝업 관계 목록이 `cardRelations`를 쓴다(`src/scripts/fragments.ts:394`).
3. 카드 푸터 "N개의 연결"이 상대편까지 센다. 페이지의 카드 12개가 전체 컬렉션을 12번 훑지 않도록 `render()`에서 파트너 맵을 한 번만 만든다.

편집 폼은 이번 단계에서 건드리지 않았다. 동작하지 않는 제거 버튼을 먼저 띄우지 않기 위해서다. → **R02**

- GPA 팝업: "아직 연결된 개념이 없습니다" → **"후속 개념 · EPT"**
- GPA 카드 푸터: `0개의 연결` → **`1개의 연결`**
- EPT 쪽 표시는 그대로(선행 개념 · GPA)

## 남은 사항

- R02(편집 폼 양방향화)는 별도 작업. 반대편에서 제거하면 상대 카드 파일이 수정되므로 충돌·권한·응답 유실 복구를 상대 카드 기준으로 다시 검증해야 한다.
- 운영 가이드에 "반대편 카드에서 관계를 지우면 발행 대기에 그 카드가 뜬다"를 적는 것도 R02에서 함께.
