# ABV01: 템플릿과 실제 콘텐츠 계약의 격리 검증 (2026-10-14, 통과)

- 판정·저장: 사용자 명시적 통과 후 승인 기록·커밋 `9a84ac9`·개발 브랜치 push 완료. 이 상태 갱신은 ABV02 검토 범위다.

- 시작 기준: `f0f58ca`. ABT02의 명시적 통과 후 승인 기록·커밋·개발 브랜치 push 완료를 확인했다. 선행 상태 갱신은 이번 검토 범위에 포함한다.
- 문제·요청: 템플릿과 현행 계약의 일치·무효 입력 실패·실제 수집 결과에 반복 가능한 실행 근거가 필요했다. 계획 ABV01에 따라 운영 콘텐츠를 고정 fixture로 쓰지 않고 합성 예시로 검증한다.
- Red: 최초 모듈 부재 실패와 assertion 실패를 구분했다. 검증용 치환 함수의 최소 구현 이후 BODY 누락이 예외를 던지지 않아 assertion 실패를 확인했다. 누락한 치환값을 차단해 Green을 확인했다. 이미 존재하는 필수 필드·ID·관계 검증은 현행 동작을 특성 검사했으며 새 결함의 Red라고 주장하지 않는다. 실제 빌드 준비 중 public 디렉터리가 없는 환경에서 복사가 실패해 선택 자산 디렉터리만 존재 시 복사하도록 수정했다. 이는 기능 Red가 아닌 준비 오류다.
- 수정: 검증용 합성 fixture 생성, 실제 컬렉션 스키마·Fragment 계약과 consts 타입 대조 15개, 독립 임시 사본 4개의 실제 Astro 빌드 검사를 추가했다. 운영 콘텐츠 경로 제외·Fragment 환경변수 제거·실패 진단 보존을 적용했다. 공개 글·카드·관계·카테고리·프로젝트·이미지와 초안/새 템플릿 제외를 확인한다. 명령을 package.json과 공통 Verify 워크플로에 연결하고 사람이 읽는 검증 결과를 추가했다. 실제 처리 엔진으로 확대하지 않았다.
- 자동 검사: 단위·통합 122개 통과, 보강 뒤 관련 15개 재검사 통과. 실제 빌드 valid·missing-title·duplicate-id·missing-target 4건 최종 통과(무효 입력은 예상한 진단과 비정상 종료를 확인). 타입 검사 오류 0·경고 0·기존 힌트 5. 기존 콘텐츠 일반 빌드 11페이지·18이미지 성공. 문서 링크 21개·diff 공백 검사 통과, 원본 src 변경 없음. Graft 66개 소스 인덱스를 갱신했다. 기존 폴더의 삭제 3건을 유지하고 이번 파일 13개만 스테이징한다.
- 사용자 확인 준비: 검증 결과 문서를 기본 앱으로 연다. 화면 변화가 없어 브라우저 조작은 요구하지 않는다. 검증 범위와 한계를 다른 AI에게 전달할 수 있는지 판정받으며 자동 검사 실행이나 diff 확인을 사용자에게 맡기지 않는다.
- 남은 제약: 미등록 카테고리·관계 쌍 중복은 현행 공통 검증이 허용한다. 이 한계도 실행 검사에 기록했으며 운영 규약을 자동 강제한다고 표현하지 않는다. 실제 OAuth·외부 저장·발행·배포와 원격 CI 실행 결과는 미확인. UI 변경이 없어 E2E는 재실행하지 않았다. 세션 인계·재실행은 다음 ABV02, 전체 완료 증거는 ABA01 범위다.
