# K01 — Decap `/admin/` 경로 제거 (2026-09-24, 판정 대기)

- 시작 기준: I03 최종 보고서 `65dee13` 통과·push. 보고서 8장의 1순위 후속 과제를 그대로 실행했다.
- 문제: 전용 작성 폼으로 전환한 뒤에도 초기 실험용 Decap CMS 화면이 남아, **5.0MB 벤더 번들이 매 배포에 실려 나갔다.** 기능은 꺼져 있었지만(백엔드 설정 없음, `noindex`) 검사 2개(`test:admin`)는 로컬 proxy가 필요해 CI 밖에 있었다.

## 먼저 확인한 것

`graft grep "admin"`으로 참조를 전부 확인했다. 지우기만 하면 되는 줄 알았으나 **운영 경로가 Decap 모듈에 얹혀 있었다**:

- `src/lib/fragment-admin.ts`의 `prepareFragmentSave`(저장 계약)를 운영 writer가 쓴다.
- 같은 파일의 `cmsConfig.backend.repo`/`.branch`가 운영 저장소·발행 브랜치 상수 역할을 했다.
- `fragment-admin-oauth.ts`의 `createOAuthTestConfig`가 **테스트 저장 설정 검증**(운영 저장소·main 브랜치·비 HTTPS 거부)까지 겸했다.

그래서 삭제가 아니라 **분리 후 삭제**로 진행했다.

## 한 일

1. `prepareFragmentSave` + `saveSchema` → `src/lib/fragments.ts`(스키마가 사는 곳)로 이동.
2. `BLOG_REPO`·`PUBLISHED_BRANCH` 상수와 `createTestWriterConfig`(구 `createOAuthTestConfig`의 검증 부분), `requireHttpsOrigin` → `src/lib/fragment-writer.ts`로 이동. Decap 설정 객체를 펼쳐 만들던 부분은 버리고 `WriterConfig`를 바로 만든다.
3. 삭제: `public/admin/`(벤더 5.0MB 포함), `src/pages/admin/`, `src/scripts/fragment-admin.ts`, `src/lib/fragment-admin.ts`, `src/lib/fragment-admin-oauth.ts`, `scripts/admin-local.mjs`, `playwright.admin.config.ts`, `tests/admin/`, `tests/e2e/admin-disabled.spec.ts`, `tests/unit/admin.test.ts`. npm 스크립트 `dev:admin`·`test:admin`도 제거.
4. 테스트 이관: `tests/unit/admin.test.ts`의 저장 계약 3건 → `tests/unit/fragment-save.test.ts`로 옮겨 유지(Decap 필드 계약 1건만 버렸다). `tests/unit/oauth.test.ts`의 "test CMS isolation"은 `createWriterConfig`로 같은 거부 조건 7가지를 그대로 검사한다.
5. `tests/oauth/login.spec.ts`의 Decap 클라이언트 의존 2건 삭제. 팝업 핸드셰이크 자체를 검사하는 3번째 건은 `/admin/`을 쓰지 않아 그대로 남겼고, 전용 폼의 로그인·취소·잘못된 origin은 `writer.spec.ts` 7건이 이미 덮는다.
6. `FRAGMENT_CMS_LOCAL` 제거: 로컬 proxy가 사라져 이 변수는 어디에서도 동작을 바꾸지 않는다. `writerConfigFromEnv`의 "로컬 모드와 동시 설정 거부" 가드와 그 단언도 함께 걷었다. **테스트 모드 + 운영 origin 동시 설정 거부는 그대로 남아 있다.**
7. `playwright.oauth.config.ts`의 서버 준비 확인 주소를 `/admin/` → `/fragments/`로 변경.

Worker(`workers/fragment-oauth/`)는 그대로다. 전용 폼의 로그인이 같은 핸드셰이크 규약을 쓰기 때문이다.
