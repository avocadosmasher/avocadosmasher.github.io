# J01 — 문서·폴더 정리와 작업 로그 분할 (2026-09-24, 판정 대기)

- 시작 기준: I01 `c055bb2`를 사용자 통과 후 커밋·push했다. 사용자가 (1) 토큰 절약을 위한 개발 로깅 방식 개선, (2) 파일·폴더 정리를 요청했다. "메뉴판을 보고 필요할 때만 로그를 찾아보는" 방식을 제안받았고, 비판적 검토 후 아래 형태로 합의했다.
- 문제 측정: 루트 `.md` 15개가 168,000자였고 그중 `Fragment-개발기록.md` 하나가 **76,519자(46%, 673줄, 항목 50개)**였다. 한국어라 이 파일 하나가 대략 6만~9만 토큰이다. 세션마다 필요한 것은 "지금 어디까지 왔나" 몇 줄인데, 그것이 나머지 74,000자와 한 파일에 묶여 있었다.
- 진단: 크기가 아니라 **수명이 다른 정보가 한 파일에 섞인 것**이 원인이다. 하루짜리 상태, 영구적인 결정 근거, 사실상 1회용인 검증 기록이 함께 있었다.
- 선택: 메뉴판만 두면 "혹시 몰라" 원문을 열어 두 번 읽게 된다. 그래서 (1) 메뉴판 한 줄에 **결론**을 담고, (2) 아카이브를 월별이 아니라 **항목당 1파일**로 잘라 필요한 하나만 열 수 있게 했다. 원문은 한 글자도 줄이지 않았다.
