- 문제·요청: 현재 데이터 스키마는 일부 공백 문자열·자동 보정 날짜·미확정 치환값을 허용할 수 있음. 파일을 변경하지 않고 문서별 오류 위치와 원인을 반환하는 기반 모듈이 필요함.

- 수정: 기존 글·Fragment 스키마를 공통 ESM 모듈로 분리해 실제 빌드·저장·검사에서 공유함. 기존 Fragment export 유지함. 단일 문서 형식·달력 날짜·빈 필수 값·미완성 템플릿·미지원 Fragment 필드를 진단함. Markdown 코드 예제는 치환값 검사에서 구분함. 모듈 자체에 파일 읽기·쓰기·네트워크 기능을 추가하지 않음.
