# M02 — 개발 방법론 검토 보완 (2026-09-27, 판정 대기)

- 시작 기준: M01 개발 방법론 HTML 및 관련 기록이 스테이징된 상태, 사용자 판정 전. 사용자가 검토 결과의 보완을 요청했다.
- 문제·요청: 다음 커밋에서 상태를 갱신하면서 판정 대기 상태에서는 새 작업을 금지하는 규칙이 충돌했다. 새 저장소의 첫 커밋은 HEAD가 없어 내장 승인 예제가 실패했다. 적용 범위·훅 보장 범위·실적 수치도 과도하거나 불명확했다.
- Red: 앞선 검토의 격리 저장소 실행에서 기존 예제의 최초 approve 실패(종료 1), 승인 후 미스테이징 수정의 check-commit 허용(종료 0)을 확인했다. 문서 변경에는 별도 억지 실패 테스트를 만들지 않았다.
- 수정: 실제 판정 기록·커밋과 문서 갱신 지연을 구분하고 동일 변경의 재승인을 금지했다. 상태 갱신은 다음 검토 범위에 포함한다. 스킬의 적용 조건과 완료 산출물을 합의한 범위로 한정했다. 내장 예제는 첫 커밋의 base를 null로 처리한다. 훅이 검증하는 범위와 미스테이징·미추적 변경, 병합·여러 커밋 push의 한계를 명시했다. I02 검사 시점, M01 이전 로그 수, K01 이후 수치를 구분하고 Graft 절차 및 작업 ID와 커밋 단위의 차이를 추가했다.
- 자동 검사:
  - `node --test --test-reporter=dot scripts/development-methodology.test.mjs`: 6개 통과. HTML에서 추출한 승인 코드를 임시 Git 저장소에서 검증한다. 최초·일반 커밋 승인과 push 검사, 승인 없음·변경 트리·추가 커밋·ref 삭제 차단, 미스테이징 수정의 범위를 확인했다. 실제 Blog의 승인 정보는 변경하지 않았다.
  - `python -X utf8 .../skill-creator/scripts/quick_validate.py <임시 스킬 경로>`: 통과. HTML에서 추출한 SKILL.md 형식을 검증했다. Windows 기본 cp949 오류 후 UTF-8로 실행했다.
  - Playwright Chromium: 표시된 스킬과 원문 일치, 다운로드 파일과 원문 일치, 페이지 JS 오류 없음, 390px에서 페이지 전체 가로 넘침 없음. 1280px·390px 캡처 확인. 코드 블록 내부는 기존처럼 가로 스크롤한다.
  - `git diff --check`: 통과. 앱 코드·빌드 설정 변경이 없어 전체 앱 빌드는 실행하지 않았다.
- 남은 제약: 브라우저 실제 클립보드 복사는 미검증. 내장 예제만 보완했으며 이 저장소에서 실행 중인 승인 스크립트·훅은 변경하지 않았다. 사용자에게 문서 표현의 적절성과 복사 동작을 확인 요청한다. M01·M02는 판정 대기이며 커밋·push하지 않았다.
