- [2차 개발계획](../plan/AI-콘텐츠-자동화-2차-개발계획.md)의 범위와 보장 수준을 결정하는 기록이다.

## 1. 저장소 Tool부터 구현

- 확인된 전제: 사용자는 콘텐츠 검사기·공통 적용 Tool·Hook·CI의 역할 설명을 확인한 뒤 후속 진행을 요청했다.
- 선택: Node.js 기반 CLI와 재사용 가능한 판단 모듈을 먼저 구현한다. 확신도 높음.
- 대안: 웹 화면부터 확장하면 계정·API·화면·기존 작성 흐름까지 한 번에 바뀐다. 문서만 추가하면 이번 목표인 기계적 강제를 제공하지 못한다.
- 효과: 외부 쓰기 없이 파일·재실행·충돌을 검증할 수 있다. 웹 사용자는 이번 결과를 직접 호출할 수 없으며 연결은 후속 단계다.
- 잘못 정했을 때의 비용: 입출력 계약을 공유하지 않으면 나중에 웹용 로직을 중복 작성할 수 있다. CLI 입출력과 핵심 판단을 분리해 비용을 줄인다.

## 2. 기존 위반과 신규 위반을 구별

- 확인된 전제: 실제 글 2개·Fragment 2개에 미등록 Infra가 있다. 1차는 기존 콘텐츠를 임의로 옮기거나 카테고리를 바꾸지 않기로 했다.
- 선택: 규칙 ID·경로·문제 값으로 고정한 예외 목록을 버전 관리하고 새 위반을 차단한다. 확신도 높음.
- 대안: 현재 모든 위반을 실패시키면 초기 검사부터 막힌다. Infra를 임의 등록하면 사이트 설정과 시각 정책이 바뀐다. 기존 파일 전체를 검사에서 제외하면 새 위반도 놓친다.
- 효과: 기존 제목 수정과 신규 콘텐츠 검사를 함께 지원한다. 기존 예외를 해소하려면 별도 합의가 필요하다. 예외 추가는 도구가 자동 승인하지 않는다.
- 잘못 정했을 때의 비용: 예외가 넓으면 우회가 생긴다. 값과 경로를 함께 고정하고 예외 상태도 결과에 표시한다.

## 3. 실제 파일과 적용 기록을 함께 확인

- 선택: 공유 가능한 최소 적용 기록은 `.content-ops/receipts/`, 실행 중 잠금·저널은 Git 제외한 `.content-ops/local/`에 둔다. 확정 요청 원문은 명시적 파일 입력으로 제공한다. 확신도 중간.
- 대안: 기록을 로컬 임시 폴더에만 두면 다른 컴퓨터에서 재시도를 확인하지 못한다. 본문·채팅·토큰 전체를 기록에 복제하면 공개 저장소의 자료 노출과 중복 보관 범위가 커진다.
- 효과: 작업 식별자와 입력·대상 지문으로 재시도를 구별하며 실제 원본을 다시 읽는다. 적용 기록만으로 사라진 확정 본문을 복구하지 못하므로 요청 원문도 인계해야 한다.
- 잘못 정했을 때의 비용: 기록 형식이 바뀌면 마이그레이션이 필요하다. 버전 필드와 명시적 미지원 진단을 두고 입력 계약 ACTC02에서 고정한다.

## 4. 로컬 적용과 사람의 승인 분리

- 확인된 전제: 로컬 변경안 준비는 허용되지만 커밋·push에는 현재 변경의 명시적 통과가 필요하다. 기존 훅은 승인받은 트리와 기준 커밋을 검사한다.
- 선택: 적용 Tool은 로컬 파일까지만 바꾼다. 도구가 Git 커밋·push·승인 기록을 자동 실행하지 않는다. 확신도 높음.
- 대안: 요청서의 approved 값이나 호출 플래그를 사람의 승인으로 믿으면 AI가 직접 만들어낼 수 있다. 별도 승인 서버는 인증·권한·외부 서비스 범위를 추가한다.
- 효과: 기존 사용자 판정 경계를 유지하면서 내용 검사·부분 수정·충돌을 코드로 강제한다. 모든 AI 행동과 외부 편집기 쓰기를 완전히 통제한다고 주장하지 않는다.

## 5. 개발 절차는 현재 사용자 규칙 유지

- 확인된 전제: 설치된 gated-tdd 1.5.0은 자동 커밋·예산 장치를 소개하지만 저장소 AGENTS는 모든 변경에 명시적 사용자 통과를 요구한다. 새 장치와 설정은 현재 저장소에 없다.
- 선택: 이번 개발은 현재 승인 훅과 사용자 판정 절차를 유지한다. 스킬 자산을 덮어쓰거나 보호 범위를 완화하지 않는다. 확신도 높음.
- 대안: 스킬 버전만 보고 훅을 업데이트하면 검토받은 승인 체계가 바뀐다. 자동화 2차 기능과 개발 절차 교체를 한 작업에 섞지 않는다.
- 효과: 계획의 기능·정책 결정은 사용자에게 확정받고, 각 작은 구현은 자동 검사·기록 뒤 기존 방식으로 통과받는다. 절차 자체를 바꾸려면 별도 요청과 범위 합의가 필요하다.

## ACTV01의 기존 스키마 공유와 추가 정책

- 선택: 기존 글·Fragment 스키마를 Node와 Astro에서 함께 읽는 공통 ESM 모듈로 분리했다. 기존 import 경로의 Fragment 스키마 export는 보존한다.

- 효과: 실제 빌드·저장 계약은 그대로 유지하고, 별도 검사기에만 공백 문자열·엄격한 달력 날짜·치환값 규칙을 추가한다. Fragment 미지원 필드는 기존 원문 저장기의 제한과 맞춘다.
- 치환값 경계: 대문자 템플릿 표시를 메타데이터와 일반 본문·링크·이미지 경로에서 찾는다. Markdown 코드 블록과 인라인 코드는 설명 자료로 허용한다. 본문 품질이나 모든 템플릿 언어를 검사한다고 표현하지 않는다.

## ACTV02의 전체 관계와 기존 예외 경계

- 확인된 전제: ACTV01 사용자 통과·`7a37ee1` 개발 브랜치 push 완료됨. 계획에 기록한 미등록 Infra 4건 외에 현재 수집 콘텐츠의 새 위반은 발견되지 않음.
- 선택: 문서 집합·등록 카테고리·예외 목록을 받는 순수 모듈에서 형식 검사와 전체 정책 검사를 결합함. 경로순으로 검사해 파일 열거 순서와 무관한 결과를 반환함. 확신도 높음.
- 예외 선택: `config/content-policy-baseline.json`에 버전 1과 규칙·실제 경로·문제 값의 정확한 조합만 허용함. `Infra` 전체 허용·와일드카드·잘못된 버전·중복 예외를 거절함. 같은 파일 제목 수정은 예외를 유지하지만 다른 파일·다른 값에는 적용하지 않음.
- 대안: 기존 파일 전체 제외는 그 파일의 새 오류도 숨김. 모든 미등록 카테고리 차단은 기존 콘텐츠를 임의 수정하도록 압박함. 정확한 예외의 별도 보고를 선택함.
- 관계 선택: 같은 ID는 별도 파일이어도 중복임. 같은 두 카드의 관계는 방향과 유형에 무관하게 한 번만 허용함. 현재 관계 편집기의 제한과 계획을 따르며 기존 런타임 검증기는 변경하지 않음.
- 불완전한 입력: Fragment 형식 오류·중복 경로·중복 ID로 전체 대상을 확정할 수 없으면 `graphChecked: false`로 반환함. 잘못 읽힌 카드를 없는 카드로 추정해 관계 검사가 끝났다고 보고하지 않음. 등록 카테고리 오류와 단순 관계 오류는 별도 진단함.
- 효과: 실패 진단과 허용된 기존 문제를 구별함. 현재 발생하지 않는 예외는 `unusedExceptions`로만 보고하고 자동 삭제하지 않음. 모듈이 받지 않은 파일까지 검사했다고 주장하지 않음.
- 잘못 정했을 때의 비용: 파일 이동·카테고리 이관 시 예외가 자동으로 따라가지 않음. 별도 검토로 예외를 조정해야 함. 예외 목록을 사람이 임의 확장하는 행위 자체를 인증으로 차단하는 기능은 없음.
- 후속 경계: 실제 저장소의 수집·정적 설정 로딩·CLI 종료 코드는 ACTC01에서 구현함. 이번 통합 검사는 현재 글 로더 경로와 실제 CATEGORIES를 읽어 모듈을 검증하며 파일·네트워크를 수정하지 않음.

## ACTC01의 읽기 전용 실행과 실패 보고

- 확인된 전제: ACTV02 사용자 통과·`b5a936b` 개발 브랜치 push 완료됨. 실제 현재 입력은 고정된 콘텐츠 경로와 정적 CATEGORIES 객체임.
- 선택: `node scripts/content-check.mjs`와 npm 별칭 `content:check`로 같은 검사기를 호출함. 기본 대상은 스크립트 소속 저장소이며 `--root`로 사본을 명시함. 다른 터미널 폴더에서 실행해 대상이 바뀌는 혼동을 줄임.
- 출력 선택: 기본은 한국어 안내, `--json`은 같은 결과의 JSON임. 종료 코드는 0 통과·1 콘텐츠/입력 오류·2 명령 사용 오류로 구별함. 순수 JSON 사용 시 npm의 별도 안내를 피하도록 Node 직접 명령을 안내함.
- 설정 선택: TypeScript AST로 export const CATEGORIES의 정적 키·문자열 값만 읽음. 실행·계산·별칭·spread·중복 선언과 키는 추측하지 않음. 예외 JSON도 중복 키를 묵인하지 않음. 확신도 높음.
- 수집 선택: 글은 하위 index.md, Fragment는 하위 .md이며 draft도 검사함. 숨김 경로와 평면 글은 수집하지 않음. 필수 폴더 누락과 링크/junction은 지원 범위 밖 오류로 표시함. Astro가 읽을 수 있는 모든 배치를 지원한다고 해석하지 않음.
- 대안: 없는 폴더·링크를 건너뛰면 잘못된 저장소 지정이나 빠진 카드가 정상처럼 보일 수 있음. 지원하지 않는 입력을 명시적으로 거절하는 쪽을 선택함. 현재 소스에는 추가 위반 없음 확인함.
- 실패 보고: 설정·읽기 실패는 먼저 발견한 문제로 중단함. `collectionComplete: false`로 표시하고 개수는 중단 전 읽은 문서 수임을 설명함. 메타데이터가 불완전하면 전체 관계 검사도 미수행으로 표시함.
- 한계·비용: 동적 CATEGORIES나 링크 기반 배치로 바꾸면 검사기 지원도 별도 조정해야 함. 검사 중 외부 편집을 포함한 원자적 스냅샷은 보장하지 않음. 검사 이후 변경은 다시 확인해야 하며 적용 직전 기준 검증은 후속 도구 범위임.

- 확인된 전제: ACTC01·C1 사용자 통과·`ee078d9` 개발 브랜치 push 완료됨. 1차 요청서는 웹·삭제·발행·경력·근거·승인까지 포함하는 인계 양식이며 이번 도구 범위보다 넓음.

- 대안: 느슨한 인계 YAML을 그대로 실행하면 누락 값·희망 발행 단계·AI가 적은 승인 문자열이 적용 조건과 섞임. 명시적 입력 확정 비용을 감수하고 기계 계약과 인계를 구별함.
- 비교 선택: 요청 객체 키 순서와 빈 목록 기본값만 정규화함. 본문 바이트 차이·배열 순서·대상·자산 지문은 보존함. 기준은 Git SHA와 구별한 실제 파일 SHA-256이며 새 문서 부재만 null로 표현함.
- 계획 선택: 요청 지문과 모든 대상의 전후 지문을 계획 지문으로 묶음. 변경하지 않는 본문·관련 파일도 대상 상태 목록에 남겨 자산만 완료된 상태를 전체 완료로 오인하지 않음. 확인한 지문과 다른 계획은 거절함.
- 기록 선택: 공유 완료 기록에는 비교용 최소 정보만 보관함. 본문·채팅·토큰·승인은 기록하지 않음. 현재 실제 파일까지 대조해야 이미 적용됨으로 반환함. 변경 없음에는 새 완료 기록을 만들지 않음. `.content-ops/local/`만 Git에서 제외함.

- 생성 후보 선택: name·period·role·link 중 양쪽에 존재하는 값이 다를 때 별개로 구별함. 선택 필드 누락을 다른 프로젝트의 증거로 보지 않음. 후보 없음은 추가, 하나와 전체 값 일치는 변경 없음, 하나의 다른 내용은 충돌, 여러 후보는 모호함임. 같은 이름이라도 양쪽의 확정 기간이 다르면 별개일 수 있음. 다른 이름으로 표현한 같은 프로젝트의 의미 중복까지 탐지하지 않음.
- 수정 선택: 정확한 원래 전체 selector가 하나일 때만 수정하며 결과가 다른 항목과 겹치면 중단함. 원래 전체 값이 중복이면 첫 항목을 택하지 않음. 실제 후보 전체 값을 JSON candidates와 기본 출력으로 제공함. 표시용 번호는 입력 식별자가 아님.
