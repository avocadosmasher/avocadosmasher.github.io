## 1. 확인한 문제와 검토 범위

스킬 간 파일명 충돌, 인계·동시 작업·복구, 단순 대안·전환 비용을 세 서브 에이전트가 독립적으로 읽기 전용 검토함. 실제 덮어쓰기 사고는 발견하지 않았으며 현행 지시와 프로그램 계약에서 발생 가능한 문제를 구분함. 구현이나 실제 운영 적용을 검증한 결과는 아님.

| 확인 근거 | 발견 |
| --- | --- |
| [AGENTS 공통 절차](../../AGENTS.md), [콘텐츠 규약](../guide/AI-콘텐츠-작업규약.md) | 콘텐츠에도 개발 로그·STATUS 갱신 의무가 적용되어 local/HANDOFF만 추가하면 모순 남음 |

검토한 gated-tdd 1.6.0은 루트 STATUS와 개발 로그의 고정 배치를 사용함. 작성 스킬과 조합할 때 개발 절차를 콘텐츠 작업에 자동 전파하지 않도록 저장소 규칙에서 범위를 정해야 함. 설치된 외부 스킬 자체는 수정하지 않음.

## 2. 선택·대안·비용

| 선택지 | 장점 | 남는 문제·판단 |
| --- | --- | --- |
| STATUS 이름만 변경 | 이름으로 개발·콘텐츠 구별 가능 | 공용 갱신 의무가 남고 기존 스킬/참조 수정만 커져 단독 적용 제외함 |
| 루트 STATUS를 전체 작업 목록으로 확대 | 한 곳에서 조회 가능 | 공용 쓰기 지점·개발/콘텐츠 대기 혼선이 커져 제외함 |
| 모든 초안·상태를 docs에 버전 관리 | 다른 체크아웃에서 조회 용이 | 미완성 본문·원자료가 Git 이력에 남고 상태 갱신도 저장 판정 대상이 되어 기본값에서 제외함 |
| local 요청 폴더 하나로 관리 | 확정 요청 한 건의 실행에 가장 단순함 | 글 기획부터 여러 요청을 잇는 범위에는 초안·후속 작업 연결이 분산됨 |
| local 작업 폴더 안에 개별 요청 보관 | 초안·메모와 불변 요청을 구분하고 여러 변경을 한 작업으로 인계 가능 | 폴더 한 단계와 명시적 인계 비용을 감수하는 안으로 채택함 |

확신도 높음. 이번 목표가 확정 입력 한 건의 실행만이 아니라 다른 작성 스킬의 기획·초안·후속 수정을 잇는 것이라는 사용자 맥락을 반영함. 상위 폴더를 별도 Tool ID/스키마로 만들 필요는 없으며 경로 관례로 한정함.

## 3. 확정 경계

- 루트 STATUS 이름·개발 관리 역할 유지함. 개발·콘텐츠·혼합 작업의 읽기/갱신과 로그 규칙을 공통 지침에서 분리함. 콘텐츠 진행을 위해 개발 로그/STATUS를 갱신하지 않는 방향으로 후속 구현함.
- 작업공간은 `.content-ops/local/tasks/<작업명-고유값>/`로 정함. 기존 작업을 찾아 재개하며 세션마다 새 작업 폴더를 만들지 않음.
- 초안·HANDOFF·메모는 가변 자료임. 계획에 사용한 확정 요청 원문은 보존하고 변경이 확정되면 새 개별 요청을 연결함. 같은 request_id에 다른 본문을 덮어쓰지 않음.
- 기존 receipt·잠금·journal·stages 위치/형식과 CLI 계약 유지함. 새 task_id 필드·DB·전역 잠금·승인 문자열 저장소는 추가하지 않음.
- 콘텐츠 진행 기록은 HANDOFF, 실제 적용 증거는 파일/receipt/journal, Git 저장은 실제 커밋/push, 사용자 판정은 대화로 구분함. 메모의 완료·승인 문구를 자동 판정 근거로 사용하지 않음.
- 같은 초안은 한 AI가 작성 담당을 맡고 한 요청은 지정 worktree에서 실행함. 같은 worktree의 Git 스테이징·승인 범위가 자동 분리된다고 가정하지 않음.
- local 원문은 기본 Git 제외 유지함. 다른 환경에는 필요한 초안·확정 요청·원래 계획/지문·준비 자산과 실제 root/branch/기준을 명시적으로 전달함. 활성 실행·중단 복구 자료의 무조건 복사·자동 재개는 지원하지 않음.
- 폴더 분리는 협업 정책임. 다른 스킬의 루트 하드코딩·임의 파일 쓰기를 물리적으로 차단하는 권한 경계로 설명하지 않음.
- 사용자 통과 전 승인·커밋·push 금지와 기존 훅을 유지함. 새 스킬 버전의 자동 진행 지침을 근거로 저장소 승인 절차를 완화하지 않음.

## 4. 전환 순서·재검토 조건

- 진행 확인: ACWP01 사용자 통과·`7d3fb16` 개발 브랜치 push 완료함. ACWR01에서 AGENTS·CLAUDE·공통 규약의 분류/기록 범위를 반영함. 실제 콘텐츠 변경의 사용자 통과와 기존 훅은 유지하며 세부 템플릿·복사 안내·격리 실제 사용은 후속 단계로 남김.
- ACWT01 연결: ACWR01도 사용자 통과·`be3fba7` 개발 브랜치 push 완료함. 작업공간 예시는 templates/ai-content/workspace에 두고 실제 콘텐츠 수집 경로 밖을 유지함. HANDOFF와 가변 초안·확정 요청을 나누며 인계 YAML의 작업공간/관찰 정보는 기계 JSON 필드가 아님을 명시함. 기존 스킬의 출력 경로 지원 여부를 확인하되 외부 패키지 자체는 수정하지 않음. 실제 CLI 적용·복구·인계 회귀는 ACWV01에서 검증함.
- ACWV01 검증: ACWT01 사용자 통과·`454f973` 개발 push·정확한 커밋 원격 CI 성공 확인함. 새 실제 CLI 통합 7개로 두 작업·카테고리/글/후속 요청·재실행·오래된 메모·다른 입력·자산 누락/전달·다른 기준·저널 없는 recover 거절을 검증함. 기존 중단/복구 41개·Git/CI 22개 포함 전체 616개 통과, 타입 127파일 오류/경고 0·기존 힌트 5 확인함. 다른 컴퓨터는 같은 기계의 독립 사본으로 모사했고 AI의 지시 해석·임의 쓰기 차단 증거로 확대하지 않음. 상세 근거와 기존 실행 코드·승인 경계는 최종 보고서에 기록함.

ACWP01 계획 등록 → ACWR01 공통 기록 규칙 → ACWT01 작업공간 예시·지시·운영 안내 → ACWV01 실제 격리 사용·인계 검증 순서로 진행함. 기존 로그·요청 예시·운영 콘텐츠를 일괄 이동하거나 완료된 2차 개발을 다시 등록하지 않음. 기존 로컬 작업은 담당·원문을 확인한 경우에만 새 관례에 연결하며 잠금/복구 자료는 이동하지 않음.

다른 컴퓨터 사이 자동 공유, 실제 동시 초안 편집, 루트 하드코딩 스킬의 실행 격리, Tool 공개 필드 변경이 필수가 되면 현재 문서 분리 범위를 넘어서는 요구로 보고 별도 계획·판정함. 현재 구조 선택을 다시 묻는 것과 구체적인 새 변경의 저장 판정을 구분함.
