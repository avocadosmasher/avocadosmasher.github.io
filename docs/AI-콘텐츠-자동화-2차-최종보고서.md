# AI 콘텐츠 자동화 2차 최종 보고서

## 결론과 현재 검토 범위

블로그 글·Fragment·카테고리·프로젝트 이력의 생성·수정을 확정 요청으로 계획하고 로컬에 적용하는 도구와, 실제 Git 대상의 콘텐츠 정책을 확인하는 훅·공통 CI를 마련했다. 다른 AI에게 넘길 때도 원래 요청·대상·기준을 유지하고, 동일 요청은 실제 결과까지 대조해 변경 없음으로 처리한다.

실행 코드 기준은 사용자 통과 후 커밋·개발 브랜치 push한 ACTH01 `8065fd6`이다. ACTA01은 운영 가이드·요청 예시 8개·호환성 검사·최종 증거를 정리한 마감 자료다. 이 자료 자체의 사용자 통과와 Git 저장은 별도로 필요하다. main 병합과 운영 배포는 이번 완료 범위에 포함하지 않는다.

평소에는 [AI에게 맡기는 방법](./guide/AI-콘텐츠-운영가이드.md)에서 시작한다. 실제 도구 사용·세션 인계·실패 대응은 [자동화 운영 가이드](./guide/AI-콘텐츠-자동화-운영가이드.md), 기계 입력은 [요청 계약](./guide/AI-콘텐츠-요청-계약.md)과 [8개 요청 예시](../templates/ai-content/operation-requests.example.json)를 사용한다. 예시 모음 전체를 CLI에 전달하지 않고 필요한 request 하나를 골라 실제 값으로 확정한다.

## 각 장치가 맡는 일

| 장치 | 역할과 실제 동작 | 한계 |
| --- | --- | --- |
| 공통 규약·지시문 | 기존 후보 조회, 사실·본문·날짜·ID 확정, 사용자 판정·인계 기준 안내 | 지시문만으로 AI의 임의 파일 편집 차단 불가 |
| Tool: plan/apply/recover | 확정 요청·기준·계획 지문 대조, 부분 편집, 재실행 결과 확인, 잠금·명시적 복구 | 자연어 본문 생성이나 사용자 승인 인증 미지원 |
| Git Hook | 기존 사용자 승인 검사 성공 뒤 실제 커밋 인덱스·전송할 커밋 tree의 콘텐츠 정책 검사 | 체크아웃별 활성화 필요, 웹 API 쓰기에는 실행되지 않음 |
| 공통 CI | 정책·타입·단위/통합·실제 CLI/격리 빌드·기존 브라우저 회귀 검사 | 대화 승인 인증과 브랜치 보호 설정을 대신하지 않음 |

같은 요청 ID에 다른 본문을 넣으면 이전 작업의 재실행으로 인정하지 않는다. 완료 기록이 있어도 파일이 달라졌으면 완료로 간주하지 않는다. 반대로 같은 작업을 같은 확정 입력으로 다시 실행해 이미 결과가 같으면 콘텐츠·기록·계획 파일을 다시 쓰지 않는다. 로컬 잠금 생성·해제와 디렉터리 시각 변화는 있을 수 있다.

## 계획의 완료 조건 대조

| 완료 조건 | 구현·확인 근거 |
| --- | --- |
| 읽기 전용 현재 콘텐츠 검사 | content-check CLI, JSON·종료 코드·위치별 진단 제공 |
| 기존 예외 보존과 새 위반 차단 | 정확한 Infra 4경로·값만 기준으로 유지, 새 카테고리·관계·형식 오류 거절 |
| 네 대상 생성·수정·재실행 | 실제 CLI/격리 Astro 빌드 회귀, 최종 예시 8개 실행 확인 |
| 요청 밖 값·경로·ID 보존과 충돌 거절 | YAML/TypeScript 필요한 범위만 편집, 기준·전체 selector·모호성 검사 |
| 잠금·중단·복구와 한계 공개 | 실제 병렬 실행·강제 종료·자료 변조·외부 편집 통합 검사, 복구 가이드 |
| 승인 유지와 공통 검사 | 원래 승인 프로그램 유지, 실제 commit/push 성공, 원격 공통 CI 성공 |
| 사용 흐름·빌드·회귀·최종 안내 | 이 보고서·운영 가이드·요청 예시 제공, 자동 판정 가능한 CLI의 사용자 재실행 요구 없음 |
| 운영 콘텐츠·URL·사용자 변경 보존 | 합성 자료는 격리 사본에만 적용, 운영 원문·설정·기존 변경·main 보존 |

개발 순서·범위는 [2차 개발계획](./plan/AI-콘텐츠-자동화-2차-개발계획.md), 선택과 실패 경계는 [설계 결정](./decision/AI-콘텐츠-자동화-2차-설계결정.md)에 기록한다. 새 웹 관리 화면·OAuth·외부 발행은 추가하지 않았다.

## 검증 증거와 버전 구분

| 검사 | 기준과 결과 |
| --- | --- |
| 최종 로컬 단위·통합 | ACTA01 자료 포함 32파일 609개 통과, 생략 없음 |
| 최종 로컬 타입 | 126파일 오류 0·경고 0·기존 힌트 5 |
| 최종 요청 예시 | 8개 모두 계약 통과, 실제 plan/apply/재apply/재plan 실행, 파일 목록·바이트·mtime 보존, 같은 ID의 입력 변경 거절, 최종 정책 통과 |
| 현재 운영 원문 정책 | 수집 글 13개·Fragment 3개, 오류 0·기존 예외 4·미사용 예외 0 |
| 일반 빌드·실제 Tool 격리 빌드 | ACTH01 로컬 일반 빌드 11페이지·18이미지 성공, 네 대상 CLI·글/이미지/검색·Fragment ID/관계·카테고리 키/색·프로젝트 필드의 Astro 출력 확인 |
| 실제 원격 CI | ACTH01 전체 608개와 기존 브라우저 62개 통과, 정책·타입·두 격리 빌드·일반 Build 성공 |

원격 증거는 [Actions 실행 39275844500](https://github.com/avocadosmasher/avocadosmasher.github.io/actions/runs/39275844500)이며 정확한 head는 `8065fd66d352caf8f856a3f579584e184b561933`이다. 2026-10-20 00:12:07~00:14:40 KST에 실행 완료했다. 두 작업 모두 성공했고, 브라우저 통과 수는 Preview 7·모바일/테마/접근성 4·대규모 카드 성능 3·OAuth 33·초안/발행 15다. 외부 운영 계정에 글을 저장했다는 의미는 아니다.

원격 608개와 최종 로컬 609개의 차이는 예시 모음의 현행 요청 계약 호환성을 확인하는 테스트 1개다. ACTA01은 실행 프로그램·훅·CI·의존성·실제 콘텐츠를 변경하지 않으므로 빌드와 브라우저 검사는 동일 실행 코드의 ACTH01 증거를 사용하고, 최종 전체 테스트·타입은 새로 실행했다. ACTA01 자료의 원격 CI는 아직 실행된 것으로 표시하지 않는다. 예시 8개의 실제 CLI 검증은 별도 격리 실행이며, 그 예시 자체를 Astro로 빌드했다고 주장하지 않는다.

원격 실행에서 production writer 검사·실패 결과 업로드·Pages 산출물 업로드는 조건에 따라 생략됐다. main 배포 작업은 실행하지 않았다. GitHub 조회의 기본 프록시 연결 실패는 허용된 네트워크 환경에서 재시도했고, 일시적 API 502도 동일 조회 재시도로 해결했다.

## 보장 범위와 남은 제약

| 상황 | 처리·한계 |
| --- | --- |
| AI 대화 세션 교체 | 원래 확정 요청·대상·기준·계획·저장 상태를 인계해야 함. 같은 자연어에서 같은 본문 생성은 보장하지 않음 |
| 의미가 비슷한 다른 콘텐츠 | 정해진 후보·키·ID·전체 항목 대조 제공. 모든 의미 중복의 자동 판정 미지원 |
| 프로젝트·카테고리 후속 편집 | 완료 기록이 consts.ts 전체 지문을 확인하므로 무관한 설정 편집도 옛 요청 재실행을 중단시킬 수 있음 |
| 외부 편집·여러 파일 적용 | 마지막 기준 확인과 rename 사이 외부 쓰기 차단·완전한 다중 파일 트랜잭션 미보장 |
| 손상·외부 수정 | 잘린 신규 파일·불완전 기록·누락/변조 준비 자료는 자동 덮어쓰기·삭제 없이 중단 |
| 중단된 잠금 | 같은 호스트의 종료 확인 소유자만 명시적 recover가 회수. 다른 호스트·불명 소유자·남은 recover 점유 자체 자동 해제 불가 |
| 로컬 준비 자료 | 본문·자산 원문을 포함할 수 있는 평문, Git 제외. 저널 생성 전 남은 준비 폴더를 전체 자동 청소하지 않음 |
| 다른 컴퓨터 인계 | 최소 완료 기록의 해시만으로 원문·로컬 복구 자료 재생성 불가 |
| 시스템 오류 | ACTK01의 파일 교체 EPERM 원인 미확정. EBUSY/EACCES 주입 검사는 실패 시 보존·재시도 근거이며 원인 규명이 아님 |
| 강제 준수 | Tool·Hook·CI의 조건만 강제. 악의적 AI의 파일/프로그램/훅 변조를 막는 권한 경계나 사용자 전용 승인 서비스 없음 |
| 작업 종류 | 네 대상 생성·부분 수정 지원. 삭제·자산 교체/이동·경력/프로필 전용 어댑터·웹 작성기 확장 제외 |

카테고리 색은 확정 문자열을 사용하며 모든 CSS 색 표현의 의미 검증은 추가하지 않았다. 프로젝트의 성과·기간·링크 사실성은 사용자가 제공한 자료를 확인해야 한다. 웹만 가능한 AI는 실제 파일 지문을 추측하지 않고 저장소 접근 가능한 AI에게 인계한다.

세부 경계는 [잠금·복구](./guide/AI-콘텐츠-잠금-복구-CLI.md)와 [Git 훅·공통 CI](./guide/AI-콘텐츠-Git-검사-CLI.md)에서 확인한다. 원래 폴더의 별도 스테이징 삭제 3건도 이 개발과 분리해 보존한다.

## 다음 행동과 후속 후보

이번 마감 자료는 화면·외부 계정 흐름을 바꾸지 않는다. 자동 판정 가능한 요청 실행은 에이전트가 완료했으므로 사용자에게 CLI 재실행이나 diff 확인을 요청하지 않는다. 사용자는 운영 방식과 보장·미보장 설명을 판정한다. 현재 ACTA01에 명시적으로 통과하면 기존 승인 기록 후 같은 검토 트리를 개발 브랜치에 커밋·push한다. main 병합·운영 공개는 별도 사용자 결정이다.

| 후속 후보 | 시작 조건 |
| --- | --- |
| main 반영·운영 인수 | 변경 범위와 병합·배포를 사용자가 별도로 결정 |
| 브랜치 보호·서버 승인·권한 분리 | 모든 AI의 임의 쓰기까지 제한할 운영 요구와 권한 설계 합의 |
| 웹 작성기의 Tool 연결 | 기존 OAuth·저장/발행 계약과 실제 계정 흐름을 포함한 별도 계획 |
| 더 강한 복구·프로젝트 영구 ID | 다중 파일 트랜잭션이나 데이터 이관 필요성을 별도 합의 |
