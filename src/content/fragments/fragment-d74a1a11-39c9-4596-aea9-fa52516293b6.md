원래 머신러닝 용어로, 모델이 학습 데이터의 잡음까지 외워 버려서 새 데이터에서는 성능이 떨어지는 현상을 말함. AI에게 코딩이나 문제 해결을 맡길 때도 같은 표현을 쓸 수 있음. 근본 원인은 두고 눈앞의 예시나 실패한 테스트 하나만 통과시키는 땜질 처방이 여기에 해당함.

**일반화 실패와의 관계**: 거의 같은 뜻으로 쓰지만 굳이 나누면 과적합은 원인이고 일반화 실패는 결과임.
- 과적합: 주어진 예시에 지나치게 맞춘 상태
- 일반화 실패: 그래서 처음 보는 입력에서 틀리는 상태

**자주 보이는 증상**
- 문제가 된 입력값 하나만 `if` 문으로 따로 처리(하드코딩)
- 테스트 기대값에 맞춘 분기를 넣어 테스트만 통과시킴
- 에러가 난 한 곳만 고치고 같은 원인이 있는 다른 곳은 그대로 둠

**과적합을 막는 프롬프트 예시**

요청할 때
> 특정 값에 하드코딩(과적합)하지 말고, IP 주소의 구조적 패턴을 일반화해서 모든 IPv4 형식에 대응할 수 있도록 처리해 줘.

> 지금 실패한 테스트만 통과시키지 말고, 이 버그가 왜 생겼는지 근본 원인부터 찾아 줘. 같은 원인으로 다른 입력에서도 문제가 생길 수 있는지 함께 확인해 줘.

> 테스트 기대값에 맞춘 분기를 넣지 말고, 테스트에 없는 입력에서도 맞게 동작하는 일반적인 규칙으로 구현해 줘.

검토할 때
> AI가 문제의 본질적인 패턴을 일반화하지 못하고 주어진 예시 데이터에만 과적합(Overfitting)되어 지엽적인 땜질 처방만 내놓지 않았는지 반드시 확인해 줘.

> 수정한 뒤에 예시에 없던 입력을 3가지 이상 직접 골라 동작을 확인하고, 각각의 결과를 알려 줘.
